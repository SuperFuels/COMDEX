\section{Layer-Sensitive Adaptive Continuation and Long-Window Cache Boundary}
\label{sec:gptoss120b-layer-sensitive-quality-20260911}

This section records a deliberately separate changed-model quality track.  The
prompt/prefill path remained the unrestricted four-expert GPT-OSS 120B path.
During greedy continuation, the runtime first selected the unrestricted top
four experts from all 128 experts in each layer.  On explicitly selected layers
only, it retained the smallest prefix of two, three, or four experts whose
cumulative unrestricted gate mass exceeded a declared threshold.  The original
surviving gate values were preserved rather than renormalized.  This changes
the neural calculation whenever fewer than four experts are retained; it is
therefore not bit-exact unrestricted GPT-OSS 120B inference.

The runtime gained an explicit, bounded layer-range parser and records the
selected layer set in every evidence report.  A second execution mode combines
the same adaptive rule with exact pool escape: expert eligibility remains
unrestricted and any winning expert absent from the resident request pool is
retrieved through the verified warehouse/L2 path.  This removed the confound in
the earlier experiment, where even nominally four-expert layers were forced to
choose from the static resident pool.  The exact I/O/compute overlap primitive
was also made composable: unchanged four-expert layers may overlap L2 delivery
with useful expert arithmetic, whereas reduced two/three-expert layers use the
existing reduced native kernel.

\subsection{Static-pool layer restriction: stopped}

The first candidate applied a preserved-mass threshold of 0.80 only to layers
24--35 but continued to constrain all continuation routes to the static
request pool.  Over the 38-position response it made 6 two-expert, 201
three-expert, and 1,161 four-expert layer decisions and reached 4.2875 response
tokens/s on its settled pass.  The two runs were internally bitwise repeatable,
but the decoded text truncated the source amount to ``EUR 287\ldots'' and did
not produce a valid extraction.  The branch is therefore
\texttt{STOPPED\_QUALITY\_FAIL}; its speed is not promoted.  The canonical
report SHA-256 is

The report/receipt file SHA-256 values are

and

\subsection{Unrestricted routing on layers 24--35: coherent but truncated}

The next candidate retained unrestricted router winners and exact pool escape,
while applying the same 0.80 threshold only to layers 24--35.  Its settled
38-position continuation reached 1.9083 tokens/s with only three SD fallbacks.
It made 4 two-expert, 225 three-expert, and 1,139 four-expert layer decisions.
Routes, final hidden states, step logits, and tokens repeated bitwise across the
two executions.  The decoded trace correctly identified invoice
\texttt{A-104} and remained coherent, but the fixed 64-position experimental
window ended immediately before printing the requested amount.  This result is
neither a quality failure nor a quality promotion; it is retained as
\texttt{INCONCLUSIVE\_OUTPUT\_WINDOW}.  The canonical report SHA-256 is
\texttt{82337728942312494dcca37952c6e60694e26412897d0ef07ffcffe4c7c85fea}.
The report/receipt file SHA-256 values are

\texttt{1cb7a7a2f719729b8017bbe73757ce484da5c9973137503dc894570516328ab4}.

\subsection{Unrestricted 0.85 adaptive policy: quality pass, speed failure}

To remove the output-window ambiguity, an 80-position paired run applied the
more conservative 0.85 preserved-mass threshold across layers 0--35.  Across
the 54-position response, the settled pass made 9 two-expert, 474 three-expert,
and 1,461 four-expert layer decisions.  Both executions produced the same
routes, final hidden states, logits, and token sequence.  The decoded answer was
coherent structured JSON containing both required values exactly:
\texttt{A-104} and \texttt{EUR 287.50}.  This is the first clean extraction
quality pass for the unrestricted-route adaptive formulation.

It was not a speed promotion.  The longer generation exceeded the useful
working set of the 20~GiB demand-admitted L2 cartridge.  The two passes incurred
462 and 451 SD fallbacks and approximately 68.10 and 68.24 decimal GB of L2
delivery.  Continuation rates were only 0.4476 and 0.4672 tokens/s; settled p50
and p95 token latencies were 1.9489 and 4.1650 seconds.  Thus the neural policy
passed this frozen quality case, while the long-window cache policy thrashed and
failed the operational speed gate.  The decision is
\texttt{QUALITY\_PASS\_STORAGE\_NOT\_PROMOTED}.

The canonical report SHA-256 is

and

\subsection{Interpretation and next gate}

The experiments separate two previously entangled failure modes.  Static pool
restriction can damage output even when only late layers reduce their expert
count.  Unrestricted winner selection with exact escape and a conservative
gate-mass rule can preserve this extraction result, but a 20~GiB scan-prone L2
cartridge cannot sustain the longer response.  Therefore lowering the mass
threshold is not the next justified action.  The next gate composes adaptive
selection with I/O/compute overlap on unchanged four-expert layers and replaces
the long-window scan behaviour with a bounded admission policy.  It must retain
the exact extracted values and improve settled throughput; otherwise the branch
is stopped.  Broader arithmetic, reasoning, and business hold-outs remain
mandatory before any general quality claim.

\subsection{Two-touch exception admission plus selective overlap}

The long-window failure was traced to immediate admission of every non-core L2
exception.  The 1,357 resident protected cartridge entries consumed almost the
entire 20~GiB capacity, leaving a small unprotected tail in which one-use
experts repeatedly displaced potentially reusable exceptions.  A bounded
two-touch admission rule was added: protected cartridge entries remain
immediately admissible, while an exact non-core exception is served transiently
from the authoritative SD warehouse on first demand and may occupy L2 only
after a second demand.  This is a cache-policy change only; it does not alter
router eligibility, gates, weights, or expert arithmetic.

The rule was composed with I/O/compute overlap on the 1,146 response layers
that still used four experts.  Two- and three-expert adaptive layers retained
the reduced native kernel.  The same 80-position prompt, 0.85 preserved-mass
policy, 8~GiB request pool and 20~GiB cartridge were rerun twice.  Both runs
again produced identical routes, hidden states, logits, and token sequences,
and decoded to the same correct JSON containing \texttt{A-104} and
\texttt{EUR 287.50}.

Continuation rates were 0.5760 and 0.5310 tokens/s, giving a two-pass median of
0.5535 tokens/s.  Against the immediately preceding identical neural policy
without two-touch admission/overlap (0.4574 tokens/s median), this is a 21.0\%
improvement.  Median SD fallbacks fell from 456.5 to 386 (15.4\%), median L2
evictions fell from 456.5 to 162 (64.5\%), median p50 token latency fell from
2.0233 to 1.7287 seconds (14.6\%), and median p95 latency fell from 4.2528 to
3.5280 seconds (17.0\%).  The candidate therefore materially reduces cartridge
churn and improves long-window performance without losing this frozen quality
case.

The decision is \texttt{ADVANCE\_CACHE\_STABILITY\_NOT\_SPEED\_FRONTIER}.
The approximately 21\% gain is real but does not constitute the target
orders-of-magnitude breakthrough, and the present two-run comparison does not
separate the individual contributions of admission and overlap.  The canonical
report SHA-256 is
\texttt{97315d857063d48511c17ca1c9f171d6219a89b55a9210921cde58440b69b4cf}.
The report/receipt file SHA-256 values are
\texttt{360a18348b98b90be2dabf9e4b05e1d78f9c6f0471859ad13ad085ac468f5df2}
and
\texttt{56613356d1a39334b661c307afe7533cc183d51fad9367568ed270511997444c}.

\subsection{Frequency-gated exception admission}

An offline reuse audit of the same unrestricted-route trace found 444 unique
non-cartridge exceptions.  Of these, 249 appeared only once in one 80-position
pass, 97 appeared twice, and only 98 appeared at least three times.  The
two-touch rule therefore still admitted many low-frequency entries when the
paired execution repeated the request.  The admission mechanism was generalized
without inspecting prompt text: the number of observed demands required before
L2 admission is now explicit, bounded, and written into the evidence report.

A three-touch candidate was run with every other neural and storage setting
unchanged.  It produced exactly the same token array as the two-touch candidate
(token-array SHA-256
\texttt{1981c74470815ed080ccb8af3c654ba068dbb3726b46fe44b962bca35c75b4dd}),
remained internally bitwise repeatable, and decoded to the same correct JSON.
Continuation rates were 0.6522 and 0.7907 tokens/s, a median of 0.7215 tokens/s.
This is 30.4\% faster than the two-touch composite and 57.7\% faster than the
immediate-admission 0.4574-token/s control for the identical neural policy.

Median SD fallbacks fell to 289, 25.1\% below two-touch and 36.7\% below the
immediate-admission control.  Median L2 evictions fell to 56, 65.4\% below
two-touch and 87.7\% below immediate admission.  Median p50 token latency fell
to 1.3194 seconds and median p95 fell to 2.9790 seconds, improvements of 34.8\%
and 30.0\% respectively against immediate admission.

The decision is \texttt{PROMOTE\_THREE\_TOUCH\_EXCEPTION\_ADMISSION} for this
80-position extraction quality track.  This is a material cache-policy
breakthrough, but it remains a single-family, two-pass changed-model result and
still does not reach the exact short-window frontier or the 30--50-token/s
programme target.  The canonical report SHA-256 is
\texttt{8bb4ff5b8e97d6e7d1fbae65a5bff7d9df4d0ace8763ffce0b11f47549119259}.
The report/receipt file SHA-256 values are
\texttt{10c82534b8b26f40c0c69bffba4b30fc14643adce7bf59001ff1bc33085915b8}
and
\texttt{6811c48f2a35214f53cd58e6b61623f55212788e0d7fd284d95fa1a8bd386bd8}.
