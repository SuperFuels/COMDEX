\section{Confidence-Gated Intermediate-Depth Token Diagnostic}
\label{sec:intermediate-depth-diagnostic}

The next exact-track investigation asked whether the final token identity becomes
stable before all 36 transformer blocks have completed.  This is materially
different from substituting cached expert outputs: no expert result, router
decision, gate, weight, hidden state, or final output was changed.  At selected
depths (after layers 18, 24, 30, 32, and 34), the diagnostic applied the original
final RMS normalisation and original vocabulary head to the live intermediate
hidden state.  It recorded the intermediate argmax token and the logit margin
between the top two candidates, while the authoritative evaluation continued
through all 36 layers.

Two frozen families were measured under the promoted three-touch, exact-pool-
escape configuration.  Arithmetic contributed nine distinct autoregressive
positions and extraction contributed ten; each was repeated in a second pass.
The full-depth path remained bitwise repeatable in final hidden state and logits,
and routes were repeatable in both runs.

The strongest signal occurred after layer 32.  Across 38 observations (19
distinct continuation positions repeated twice), unconditional agreement with
the full-depth argmax was 34/38, or 89.47\%.  A logit-margin threshold of 0.25
accepted 34/38 observations and every accepted prediction agreed with the
full-depth token.  In distinct-position terms, it accepted 17/19 positions:
8/9 arithmetic positions and 9/10 extraction positions, with 17/17 agreement.
The two mismatching positions were both rejected by the confidence gate.  After
layer 34, the same threshold accepted 17/19 distinct positions with 17/17
agreement, but only one transformer block would remain to be avoided.

This is a useful but deliberately unpromoted result.  The sample comprises only
two deterministic sequences and their repeats, not 38 independent examples.
More importantly, emitting a token after layer 32 does not eliminate the need to
construct layers 33--35 key/value state if generation continues.  A naive early
exit would therefore either corrupt subsequent-token state or defer the skipped
work rather than remove it.  The diagnostic is consequently evidence for a
possible low-latency speculative front end with exact asynchronous catch-up, not
evidence of higher sustained tokens per second.  No timing from these instrumented
runs is used as performance evidence because five additional vocabulary-head
projections were intentionally inserted into every transformer pass.

The arithmetic and extraction transformer evidence have canonical SHA-256 values
\texttt{7c8d684c1ba881cfda4e4be1706377b6aa5b05e52d5001f0d2ed04141e12d104}
and
\texttt{a32f2426d0a047853a000c1bfa62c5ef15b1bd484a6142a3f53d1c3b3295f9ae},
respectively.  The cross-family diagnostic receipt has canonical SHA-256
\texttt{1165756c694c9d2eb55d8fa1d7b0e731ec5d7b3a87ff53eba9d23b98fda97886}.
All three artifacts and an independently verified \texttt{SHA256SUMS} file are
preserved on the mounted SD evidence volume under
\texttt{early-exit-diagnostic-20260911}.

The next valid gate is an unseen-prompt evaluation of the layer-32 margin rule.
Only if it retains perfect accepted-token precision may it advance to an
asynchronous exact-catch-up prototype.  The authoritative sustained-throughput
frontier remains the promoted exact arithmetic/extraction control; this
diagnostic does not replace or lower that bar.
