# AION Compounding Authority Acquisition

## Outcome

AION has progressed from closing single autonomous goals to earning a tier-3
goal whose completion required three separately governed receipts.  The live
executive then raised the next portfolio to tier 4 without an owner selecting
the next projects.

Promoted procedure:

`procedure_open_cross_domain_authority_factory_v1`

The resulting operating chain is:

```text
later-confirmed autonomous goals
  -> raise portfolio difficulty
  -> require a cross-domain partner
  -> detect a missing outcome authority
  -> freeze semantics, candidates, properties and transfer digest
  -> return without installation
  -> reconstruct on a later invocation
  -> execute candidate tournament and counterexamples
  -> reject ambiguous or inadequate tournaments
  -> prove source-disjoint transfer
  -> retain a typed authority through CAU
  -> issue competency and authority receipts
  -> close the goal only after its later specialist consequence
  -> generate the harder portfolio
```

## New authority factory

The factory currently contains three bounded acquisition families.

| Cross-domain gap | Retained authority | Falsified alternatives |
|---|---|---|
| Distributed event processing | `IDEMPOTENT_PARTITION_FOLD` | duplicate-sensitive summation; conflict-obscuring last-write-wins |
| Contaminated observations | `ROBUST_CONTAMINATION_ENVELOPE` | arithmetic mean; fixed boundary trimming |
| Cloud deployment outcomes | `TRANSACTIONAL_CANARY_AUTHORITY` | blind rollout; health check without rollback |

The first statistical tournament produced two survivors.  AION did not choose
arbitrarily.  A clustered boundary-contamination counterexample operationalised
the already committed robustness property, rejected fixed trimming, and left a
unique robust candidate.

Tier 3 required a genuinely new authority rather than another invocation of a
tier-2 checker.  AION retained `AUTHENTICATED_EPOCH_QUORUM`, which enforces:

- unique-voter invariance;
- latest-epoch isolation;
- authenticated-vote filtering;
- quorum abstention; and
- source-disjoint reconstruction.

Raw majority and unauthenticated latest-epoch plurality were rejected.

The executive then raised all five useful-work families to tier 4.  Tier 4 adds

construct a bounded diagnostic intervention and attribute the disagreement to
evidence, environment, adapter, or method.  The existing tier-3 authority is
deliberately ineligible for this gate; the difficulty counter cannot be advanced
by replaying it.

## Governance changes

- Authority proposal and authority installation occur in different runtime
  transactions.
- A sealed transfer digest exists before candidate execution.
- A tournament with multiple surviving candidates fails closed.
- Retention is digest-bound and reconstructed through persistent learning.
- Practice goals requesting delayed closed-book reconstruction accept only a
  retention evidence kind; ordinary projects can no longer close them.
- Tier 2 publishes a concurrent useful-work portfolio; tier 3 and above publish
  all five useful-work families so authority gaps are not hidden by ranking.
- Already-running specialist work is now bound to a canonical precommitted goal
  rather than being omitted from the goal ledger.

## Claim boundary

This is a genuine compounding-autonomy and bounded authority-invention result.
It is not arbitrary verifier synthesis or unrestricted self-programming.  The
three tier-2 families, the tier-3 quorum family, their typed candidate languages,
semantic-property vocabulary, and reference oracles remain engineered.  The
tier-4 disagreement diagnostic has been generated as a live objective but has
not yet earned a receipt.
