# AION Persistent RGB Contact and Occlusion Skill Composition

## Result

AION has promoted `procedure_rgb_contact_occlusion_skill_composition_v3`.
Unlike an isolated benchmark procedure, this stage refuses to operate unless
the earlier RGB belief-state champion can be reconstructed from persistent
HexCore state. The parent cohort is content-hashed and its required visual
intervention, recurrent-state and commit-before-action invariants are checked
before the new learner receives authority.

The resulting chain is:

```text
retrieve retained RGB skill and verify digest
-> discover three visual entities without colour labels
-> intervene to identify the directly controlled object
-> hypothesise the nearest static object is a passive payload
-> falsify that hypothesis through physical contact
-> distinguish the non-physical target
-> control the payload toward the target
-> propagate a recurrent belief while the payload is occluded
-> re-identify it after emergence
-> settle and verify using hidden MuJoCo consequences
-> store a dependent executable skill capsule
-> reconstruct champion and capsule after restart
```

## Stored skill rather than stored answer

HexCore now stores a digest-pinned executable skill capsule containing:

- the exact parent procedure and parent cohort digest;
- purpose, input contract and authority limits;
- behavioural invariants;
- the ordered investigation and control method;
- diagnostic and abstention conditions;
- bounded recurrent-belief and controller parameters;
- the sealed gate digest and promoted procedure identity.

The capsule is not a transcript or a list of final object positions. It is a
compact procedural object used by the new learner. Missing, altered or
incomplete parent state causes fail-closed abstention. The capsule and promoted
champion both survived process reconstruction.

## Open visual topology and causal contact

No entity colour, shape label or role is supplied to the learner. It invents
three roles from RGB consequences:

1. the entity whose pixels move under direct action is the controlled object;
2. the initially static entity that begins moving only after collision is the
   passive payload;
3. the remaining static visual is the target.

The payload hypothesis receives credit only when an intervention moves the
candidate payload while the target remains fixed. This avoids treating visual
proximity or colour similarity as causal evidence.

During execution, an opaque band removes the payload from the RGB stream. The
learner propagates position and velocity from its recurrent belief, reduces
authority under uncertainty, then corrects the belief when the object becomes
visible again. Hidden simulator coordinates are used only by the evaluator.

## Failure-driven development

Two challengers were rejected before promotion. In the first, the occluder hid
the payload in the initial frame, making honest role discovery impossible. The
cohort was corrected so occlusion occurs only after initial grounding. In the
second, all objects were identified and tracked, but the controller stopped a
few pixels before the physical success envelope. Its early dead-zone was
removed and conservative close-range control was retested across the complete
cohort. No failed result was promoted.

## Claim boundary

This is a material demonstration of persistent skill composition: AION reloads
a governed visual skill, extends it using causal contact evidence, retains the
new procedure as a dependent executable capsule and reconstructs it after
restart. It is not unrestricted self-originated learning. The MuJoCo contact
family, typed push action, safe learning meta-algorithm and evaluation authority
remain engineered.

The next decisive physical boundary is articulated and partially observable
tool use: multiple controllable joints, objects that require sequencing rather
than continuous pushing, and transfer of the stored contact abstraction into a
different task topology or independently owned simulator.
