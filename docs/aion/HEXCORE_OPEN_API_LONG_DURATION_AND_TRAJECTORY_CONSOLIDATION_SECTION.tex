This development increment advances three dependencies of the remaining AION
programme.  First, AION acquired executable read-only interfaces from current
official documentation and transferred them to unseen targets.  Second, the
active Arena-v15 campaign was expanded from two repository authorities to four

\subsection{Open Public API Acquisition}
\label{subsec:open-public-api-acquisition}

AION inspected the official documentation for the GitHub repository API, the
PyPI JSON API, and the Open-Meteo forecast API.  For each authority it recovered
an endpoint route from source evidence, constructed a read-only HTTP
\texttt{GET} adapter, inferred a bounded response schema, and executed the
adapter against one development target and one unseen transfer target.

For response object $J$ and maximum schema depth $d=3$, the inferred schema was
constructed recursively as
\begin{equation}
 \mathcal{S}(J,d)=
 \begin{cases}
  \{k:\mathcal{S}(J_k,d+1)\}, & J\text{ is an object},\\
  [\mathcal{S}(J_0,d+1)], & J\text{ is a nonempty array},\\
  \operatorname{type}(J), & \text{otherwise},
 \end{cases}
\end{equation}
with bounded key and depth limits.  The retained contract records the method,
base authority, documentation-attested route, required response fields,
credential requirement, side-effect class, and typed schema.

The first challenger reached all six targets but was rejected because an empty
Open-Meteo query returned a permissive response.  That outcome did not prove
parameter validation.  The revised counterexample supplied a malformed
coordinate type.  The remote service rejected it, establishing that the
adapter's parameter contract was falsifiable rather than inferred solely from
a successful request.

Let $A_{\mathrm{cold}}$ be the number of documentation, diagnosis, and execution
actions required without retained adapters, and $A_{\mathrm{retained}}$ the
actions required after acquisition.  The observed information-action reduction
was
\begin{equation}
 \Delta_A=1-\frac{A_{\mathrm{retained}}}{A_{\mathrm{cold}}}=0.50.
\end{equation}

\subsection{Arena v15: Four-Authority Long-Duration Campaign}
\label{subsec:v15-four-authority-expansion}

The active Arena-v15 wall-clock campaign originally monitored the CPython and
Node.js primary branches.  It now also uses the newly acquired interfaces to
observe PyPI package metadata and Open-Meteo measurements.  This changes the
campaign from repository-only monitoring into a mixed stream of software and
environmental outcomes.

At cycle $t$, each authority $s$ supplies an independently revealed revision or
content commitment $r_{s,t}$.  Change and access failure remain distinct:
\begin{align}
 \mathrm{change}_{s,t}&=[r_{s,t}\neq r_{s,t-1}\land
                         r_{s,t}\neq\{\}],\\
 \mathrm{failure}_{s,t}&=[r_{s,t}=\{\}].
\end{align}
The learned monitoring risk is
\begin{equation}
 \rho_s=\frac{n^{\mathrm{change}}_s+n^{\mathrm{failure}}_s+1}
 {n^{\mathrm{observation}}_s+2},
\end{equation}
which selects a shorter interval for volatile or unreliable sources.  The
planned information actions and prior revisions are committed before each
cycle.  Revealed outcomes are appended to the hashed evidence ledger, while
campaign state is checkpointed by atomic replacement.

\subsection{Governed Verified-Trajectory Manifest}
\label{subsec:verified-trajectory-manifest}

Native consolidation and matched substrate comparison require a shared data
authority.  A provenance-only corpus manifest was therefore constructed over
the HexCore result history.  Each artifact $a_i$ receives commitment
\begin{equation}
 h_i=\operatorname{SHA256}(\operatorname{bytes}(a_i)),
\end{equation}
an authority classification, a capability family, a procedure identifier, and
an artifact-level split.

Four authority classes are kept separate:
\begin{enumerate}
 \item \textbf{verified positive}: CAU-promoted, provenance-bearing outcomes
 that may provide positive training authority;
 \item \textbf{verified negative}: rejected challengers retained only for
 criticism, calibration, counterexamples, and abstention learning;
 \item \textbf{protocol-only}: evaluation infrastructure that must never be
 treated as demonstrated capability; and
 \item \textbf{unresolved}: legacy or incomplete records quarantined pending
 explicit classification.
\end{enumerate}

Initial split assignment is derived from the artifact hash.  If several
artifacts name the same procedure, every copy is moved to the most conservative
existing split,
\begin{equation}
 \mathrm{sealed}>\mathrm{development}>\mathrm{train},
\end{equation}
so a procedure cannot occur in more than one split.

The manifest does not copy raw outcomes or change their authority.  It binds
future neural training and substrate evaluation to the original artifacts and
their hashes.  Rejected proposals therefore cannot silently re-enter training
as true examples, and a frozen protocol cannot be mistaken for a capability
result.

\subsection{Integrated Verification and Claim Boundary}

The combined verification covering API acquisition, trajectory governance,
the active long-duration campaign, external human and physical protocols,
Arenas v14--v17, and the AGI evidence registry passed $28/28$ focused tests.
The evidence registry now tracks 21 committed capability artifacts with
$100\%$ integrity.  No external gate is falsely marked verified, and AGI claim
authorization remains false.

The API result demonstrates bounded acquisition of three preselected,
read-only public JSON interfaces.  Documentation locations, candidate
authorities, objectives, network permissions, and safety rules remain
engineered.  It does not authorize credentials, state-changing requests,
payments, deployment, or irreversible actions.  The trajectory manifest is a
data-governance result rather than a new intelligence capability.  Arena v15
remains an active internal campaign until its real duration and outcome gates
complete.  Independent human, physical, and integrated evaluation still
require external administrators.
