## Research question

Can AION take the broad-goal projects and subgoal graphs it invented in Arena
v0, route their information actions into executable governed tools, persist the
results across interruption, revise its answer from independent consequences,
and preserve a hard separation between source evidence and execution evidence?

## Executable control plane

The implemented chain is:

```text
broad goal
  -> model-invented concepts, criteria and subgoal graph (Arena v0)
  -> selected typed actions
  -> independent governed execution
  -> action/outcome hash commitment
  -> forced runtime reconstruction
  -> proposal-only conclusion revision
  -> immutable evidence-ledger restoration
  -> consequence-alignment verification
  -> CAU promotion or rejection
```

Seven typed tool contracts were exercised:

| Tool | Independent authority |
|---|---|
| `document_reader` | Exact quotation and source-hash recovery |
| `math_tool` | Independent carbon-14 decay calculation |
| `code_reasoner` | Isolated Python execution with `-I` |
| `table_analyzer` | PDF evidence-window and CSV execution |
| `image_inspector` | Pixel variance and edge diagnostics |
| `code_reader` | Python AST and configuration inspection |
| `semantic_memory` | Restart-reconstructed retained claims |

An eighth control-plane action, `sandbox_change_probe`, modified only a
temporary copy, proved that a delayed source revision was detectable and then
confirmed that the live source hash remained unchanged.

## Real consequence examples

### Scientific learning and calculation

The model-selected mathematics action independently evaluated

\[
r = 0.5^{11460/5730}=0.25,
\]

confirming that 25% of carbon-14 remains after two half-lives. The conclusion
was required to agree with this executed result while its scientific claims
remained tied to the official source ledger.

### Code behavior

An isolated Python process compared a mutable default with a `None` sentinel.
The observed results were:

```json
{
  "unsafe": [[1], [1, 2]],
  "safe": [[1], [2]]
}
```

This independently demonstrated cross-call state retention and the fresh-list
behavior of the safer design.

### Mixed-format criticism

The Fourier CSV executor recovered three modes and found only the decoupled
mode had non-zero `bw_half`. Pixel execution verified that the PNG was
non-blank and structurally rich, but could not establish semantic axis
alignment. AION therefore retained the correct abstention rather than treating
pixel activity as proof of table--image consistency.

### Changing evidence

The governance portfolio was copied into a disposable directory, changed, and
rehash-checked. The change was detected while the live repository source hash
remained identical before and after the experiment.

## Decisive rejected challenger and architecture correction

The first post-outcome revision was rejected. Although all required tools
executed and answers aligned with the consequences, the language proposal
rewrote evidence quotations and attempted to represent execution records as
source-supported claims. Its score fell to 62.5%, provenance completeness fell
to 62.5%, and five unsafe commitments were detected.

The corrective architecture does not ask the model to preserve evidence by
instruction alone. It enforces two physically separate authority ledgers:

```text
immutable source ledger: exact quote + source ID + source hash
mutable outcome ledger:  tool + inputs + observed result + outcome hash
```

Revision may change interpretations and final conclusions, but cannot write to
the source ledger. All 53 claims emitted by the revision model were denied
source authority. The verifier recovered the valid pre-outcome source claims,
rejected one earlier invalid claim, and evaluated execution evidence separately.
This converted an instruction-level rule into an architectural invariant.

## Persistence and governance

Every action outcome is stored with a canonical hash before answer revision.
The runtime is reconstructed from disk between those stages. After the final
promotion, all projects were terminal, the generation and outcome ledgers were
retained, the champion survived restart, and no action required relearning.

## Claim boundary

Arena v1 demonstrates consequence-bearing integration across scientific,
technical, financial, software, historical, mixed-format and literary work.
It shows that real tool outcomes can correct an answer while source authority
remains immutable.

The portfolio, source set, tool schemas and outcome contracts remain engineered.
The calculator and Python probe execute real consequences, but AION did not
invent those tool implementations. Pixel diagnostics are not semantic vision.
Evidence was locally available rather than autonomously discovered on the web.
The pre-execution control is an ablation of the same retained projects, not a
separate frontier-agent baseline. Evaluation remains internally administered.

## Next frontier

Arena v2 should remove the remaining action scaffolding:

1. receive a broad unfamiliar objective with no preassembled source set;
2. invent search queries and retrieve candidate sources through a governed
   read-only acquisition layer;
3. assess publisher, recency, contradiction and evidence sufficiency;
4. synthesize typed action parameters instead of inheriting v0 tool choices;
5. execute multiple action/revision rounds under explicit cost and risk budgets;
6. learn conditional tool routing from the unnecessary-action ledger;
7. handle real delayed code, document and observation changes;
8. run matched no-memory, no-router, no-causal and substrate-only controls;
9. repeat several continual generations with backward-retention gates;
10. freeze portfolios and outcomes for independent administration.

That stage tests whether AION can determine not only how to use supplied
evidence, but what it needs to learn and which real action will resolve its
uncertainty.
