## Natural historical repository repair

### Authentic source of failure

The benchmark used three real Git repair histories and their faulty parent
revisions:

1. malformed function signature in the AgentMap discovery endpoint;
2. missing stable-message-identity helper in agent channels;
3. mismatched JSON depth between the voice bridge and worker.

The human repair revision was inaccessible during localization, test
construction and challenger search. It was opened only after one candidate had
been selected.

### Unassisted localization

AION received a natural failure report and a small read-only source portfolio.
It ranked files using observed residuals:

- parser failure location;
- private symbol use without a definition;
- producer/consumer key-depth disagreement.

The correct file ranked first in all three historical portfolios. No fault map
or target line was supplied.

### Falsification before repair acceptance

The system derived executable or static properties from the source contracts.
Examples included:

- the repaired function must compile, preserve documentation and normalize the
  request before first use;
- message identity must remain invariant to timestamp and trace fields but
  change when semantic content changes;
- text and audio fields must reach the worker at the JSON level from which the
  worker reads them.

Four incorrect repair candidates were rejected before the hidden historical
authority was opened.

## Open outcome-grounded project scientist

### Removing supplied failure labels

The successor did not receive labels such as syntax failure, missing helper or
contract mismatch. It converted raw residual features and observed outcomes
into stable opaque state identifiers:

```text
failure_state_<content-derived hash>
```

Three distinct failure states were invented and assigned without supplying
their semantic names. The names remain opaque; their operational meaning is
grounded in which experiments fail and which repair procedures later succeed.

The delayed outcome came from the sealed Git repair revision, not from the
proposal system. Counterfactual credit compared every rejected alternative

### Verified reflection

For a failed interpretation, HexCore returned only the contradiction established
by static analysis or a metamorphic test. Examples were:

- deletion would remove required request normalization;
- the stable hash must ignore several runtime aliases but remain
  content-sensitive;
- the producer nests fields that the consumer reads at the top level.

The model then received one bounded revision opportunity. This is
test-time reasoning under external criticism, not self-certification.

## Cross-language historical expansion

A sealed successor introduced two previously unused historical failures:

1. a Python frozen-dataclass constructor mismatch in the voice worker bridge;
2. an unmatched JavaScript IIFE closure in the 51,000-line desktop source.

For the Python case, AION rejected both expansion of the public dataclass
surface and deletion of runtime diagnostics. It retained the minimal repair:
move diagnostics into the existing payload while preserving types.

For JavaScript, AION executed `node --check` in a subprocess and rejected two
incorrect lexical closures before selecting the minimal IIFE closure. The
human repair remained sealed until selection.

## Claim boundary

The Git failures and human repairs are authentic, but the portfolio selection,
five repair-strategy families, static feature extractors, project size,
reflection contract and hidden evaluator remain engineered. The substrate
study contains three proposal cases and is not a broad coding benchmark.

These results establish bounded blind historical repair, outcome-grounded
failure-state invention and verified neural-symbolic reflection. They do not
establish AGI, unrestricted software engineering, or autonomous deployment.
