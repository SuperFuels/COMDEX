## 2. What AION is doing in plain English

This is not a conventional training run that updates a neural model's weights. AION is being tested as a governed apprentice wrapped around a fixed proposer model.

It is repeatedly given unfamiliar repository, API, schema, concurrency, configuration, and recovery problems. It must investigate each problem, attempt a solution, observe an independent result, diagnose failure, retain verified operational knowledge, and reuse that knowledge on later tasks.

The experiment asks a narrow but important question:

> Does the same underlying proposer become more reliable and efficient when AION supplies earned memory, verified repair knowledge, governed promotion, and retained competence?

The system deliberately compares AION against controls so that success cannot simply be attributed to the language model.

## 3. Matched experimental arms

Every cohort is evaluated through matched arms using the same mission contract, proposer cohort, tool boundaries, action budget, and independent evaluator.

| Arm | Purpose |
|---|---|
| Full AION | Memory, repair, governance, earned methods, and prior competence enabled. |
| Proposer Only | The underlying proposer attempts the task without AION's learning architecture. |
| AION No Memory | AION's surrounding machinery remains, but retained operational memory is unavailable. |
| AION No Repair | Memory may exist, but the repair mechanism is removed. |
| Cold AION | AION starts without the relevant earned competence. |

The configured proposer for this campaign is the local `qwen3:1.7b` Ollama model. The configured action budget is 40 actions per arm. The evaluator is separate from the acting arm, and self-grading cannot authorise promotion.
