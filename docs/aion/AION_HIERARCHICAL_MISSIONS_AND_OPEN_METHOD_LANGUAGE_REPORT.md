# AION Hierarchical Missions and Open Method-Language Expansion

## Result

Two governed capabilities were integrated into the canonical apprenticeship
runtime:

1. `procedure_hierarchical_capability_gated_mission_graph_v1` compiles a broad
   objective into a persistent dependency graph of strategic milestones,
   measurable work, prerequisite learning and recovery branches.
2. `procedure_open_method_language_expansion_v1` detects when none of AION's
   retained verification methods can judge that graph, invents a typed verifier,
   falsifies it and installs it only after delayed source-disjoint transfer.

The combined operating path is:

\[
\text{broad mission}
\rightarrow \text{milestones and work DAG}
\rightarrow \text{capability assessment}
\rightarrow \text{learn missing skill}
\rightarrow \text{resume blocked work}
\rightarrow \text{independent outcome}
\rightarrow \text{recovery or progress}.
\]

This supports goals such as creating a profitable website business without
pretending that “make money” is one executable action. The system decomposes
the mission into demand validation, secure construction, launch, customer
acquisition and economic verification. Missing competence becomes an explicit
learning dependency. Spending, public deployment, customer contact and revenue
transactions remain human-authority boundaries rather than autonomous actions.

The compiler queries the progressive competency ledger for each work item. A
capability below Intermediate creates a learning node and blocks only the
affected branch. A successful learning outcome can therefore release the work
without rebuilding the entire mission. Every work node records an outcome
authority and a narrow recovery sequence: diagnose origin, replan the affected
branch, then abstain or escalate if authority or evidence is missing.

## Open method-language expansion

The prior experience compiler contained six verification methods, none of
which could establish correctness of a capability-gated mission DAG. AION
diagnosed this residual and invented
`dependency_gated_mission_graph_audit`, comprising six typed read-only atoms:

- `ASSERT_ACYCLIC`;
- `ASSERT_HIERARCHY`;
- `ASSERT_CAPABILITY_PREREQUISITES`;
- `ASSERT_MEASURABLE_OUTCOMES`;
- `ASSERT_RECOVERY_BRANCHES`; and
- `ASSERT_AUTHORITY_BOUNDARIES`.

The method was precommitted before sealed scoring, developed on the live AION
mission and transferred to the website, scientific and engineering graphs.

| Measure | Result |
|---|---:|
| New methods installed | 1 |
| Source-disjoint transfers | 3 |
| Semantic counterexamples rejected | 32/32 |
| Malicious or incomplete programs rejected | 6/6 |
| Premature installs | 0 |
| Ambient authority expansions | 0 |
| Unsafe actions / live writes | 0 / 0 |

The retained method is digest-pinned in the canonical method registry. Its
interpreter is pure and read-only: arbitrary execution, network writes,
terminal-goal edits and incomplete atom sets cannot be promoted.

## Prospective autonomous use

Installation alone did not earn useful-work credit. The autonomous executive
selected the new method for a tier-6 objective and committed that goal before a
new mission-graph result existed. The hierarchy was then regenerated, the
invented verifier re-executed, and the goal arbiter closed the objective only
after five receipt roles were present:

1. later mission-graph audit;
2. source-disjoint graph transfer;
3. semantic counterexample falsification;
4. malicious-program rejection; and
5. digest-pinned runtime registration.

The autonomous consequence ledger consequently advanced to 33 confirmed goals,
with zero owner intervention, unsafe action or live-source write. The useful
portfolio remains method-driven (5 contracts, 0 fixed-family contracts).

## Claim boundary

This is an advance in hierarchical goal execution and governed expansion of
AION's verification language. It does not show that AION has created a
profitable business, nor unrestricted self-programming. Mission templates,
typed atom semantics and promotion authority remain engineered. External
business actions still require explicit human approval. The next boundary is
repeated invention of method programs for genuinely unfamiliar missions and
later real outcomes, followed by recursive invention of safe interpreter
semantics when the current atom vocabulary is itself inadequate.
