# AION HexCore — Long-Running Changing-Project Arena v3

## Status

Arena v3 is promoted internally as:

`procedure_long_running_changing_project_arena_v3_f948c2272b31`

Parent procedure:

`procedure_open_evidence_acquisition_arena_v2_32d79e5c6f41`

The result establishes persistent, consequence-bearing adaptation across four
executed project surfaces. It does not establish AGI, unrestricted autonomy,
natural multimodal understanding, human social judgment, or independent
external certification.

## Research question

Can AION retain and improve an investigation policy across changing projects
when:

- outcomes arrive only after an action commitment;
- the governing rule changes during the project;
- the process is reconstructed after every milestone;
- accumulated memory may help or mislead;
- actions have explicit costs;
- plausible but unsafe actions must be rejected before execution; and
- an unfamiliar regime may lie outside every available model?

## Architecture

The v3 control loop is:

```text
broad project objective
  -> typed parameter proposal
  -> pre-execution safety gate
  -> isolated experiment
  -> delayed independent outcome
  -> failure signature / model criticism
  -> retained repair memory
  -> costed stability monitor
  -> revise or continue
  -> checkpoint and process reconstruction
  -> weakest-family, ablation, retention and CAU gates
```

The controller never receives the hidden regime label. Each executed action
stores only a cryptographic commitment to that regime before the outcome is
revealed.

## Executed outcome surfaces

### Software execution

An isolated Python subprocess transforms event records. The contract changes
from first-occurrence deduplication to canonical latest-value serialization.
The verifier compares the output against a withheld interface contract.

### Database execution

An actual SQLite database is constructed in a disposable workspace. The
independently checked integrity requirement changes from event uniqueness to
referential integrity. Invalid writes must be rejected transactionally while
retaining committed records.

### Sensor reasoning

A CSV sensor stream is written and evaluated against a withheld continuous
reference. The noise process changes from low-amplitude distributed noise to
impulsive outliers. AION must move from mean filtering to a robust median
filter while respecting an absolute error ceiling.

### Document world model

A dependency manifest is written to disk and an upstream source changes. The
required stale-artifact model changes from direct propagation to transitive
propagation. Exact stale-set equality is checked by an independent verifier.

All files, subprocesses and databases are confined to temporary workspaces.
No live repository write is permitted.

## Continual generations

Development outcomes created a provenance-bearing mapping from project family
and raw failure signature to a verified repair. The mapping was then tested on
renamed sealed projects.

| Generation | Policy | Project success | Weakest family | Mean action cost |
|---:|---|---:|---:|---:|
| 0 | no accumulated memory | 100% | 100% | 11.00 |
| 1 | outcome memory, no router | 100% | 100% | 8.50 |
| 2 | outcome memory + costed stability router | 100% | 100% | 2.75 |

Generation 2 reduced action cost by 75.00% relative to the matched no-memory
control and by 67.65% relative to the same memory without conditional routing.
The gain was reproduced across three independent execution seeds.

The result is not merely a faster lookup. The costed monitor preserves the
current verified policy while outcomes remain stable, detects a regime change,
records the failure signature, and activates the previously verified repair
only when needed.

## Falsification, safety and unknown-model criticism

Four malicious candidates attempted code execution, network access,
destructive SQL and live-path traversal. All four were rejected before
execution. No unsafe candidate ran and no live repository file was changed.

An additional OOD sensor project exposed a response outside all three retained
filter models. After all available candidates failed independent verification,
AION recorded:

`EVENT_OUTSIDE_AVAILABLE_ACTION_MODEL_FAMILY`

and abstained. It did not select the least-bad known model or force a promotion.

## What is genuinely new

Arena v0 integrated broad goals and mixed files. Arena v1 executed selected
tools and revised answers from consequences. Arena v2 removed supplied evidence
bundles and learned to investigate. Arena v3 adds a further operational chain:

```text
learn a repair from consequences
  -> transfer it to a renamed project
  -> monitor whether the world remains stable
  -> detect a mid-project rule change
  -> invoke the relevant repair only when needed
  -> preserve competence while reducing action cost
  -> criticise the complete model family when none fits
```

This is bounded continual project adaptation with real executable contact. It
is a stronger intelligence result than a single high-scoring answer because
accumulated verified experience changes future action selection and survives
interruption.

## Claim boundary and remaining gates

The objectives, parameter spaces, adapters, four project families and outcome
verifiers remain engineered. The sensor traces are controlled rather than
independently collected. The database and software tasks are deliberately
small. The system does not yet interpret natural images or audio in this arena,
and it has not undergone independent human or external evaluation.

The following gates are explicitly **not tested** and must not be inferred from
this promotion:

1. natural multimodal semantic grounding;
2. independently judged commonsense, social and creative work;
3. matched stronger-substrate comparison;
4. projects lasting hours or days against changing external systems; and
5. externally administered hidden evaluation.

## Next acceleration contract

Arena v4 should remove the remaining finite parameter menu and connect the
control plane to independently owned outcomes. The decisive design is:

1. AION invents executable experiment programs and their typed parameters in a
   sandbox rather than choosing from a supplied finite set.
2. Outcomes come from independently maintained code repositories, databases,
   delayed public data or controlled applications.
3. Natural images, diagrams and tables enter the same project and may conflict.
4. Human-authored social and creative portfolios use several independent
   judges; disagreement is retained rather than collapsed into a false gold
   answer.
5. Stronger proposal substrates compete under identical evidence, tool, action,
   compute and CAU budgets.
6. A rolling arena runs many continual generations and measures forward
   transfer, backward retention, calibration, weakest-family performance,
   complexity and retirement/revival.
7. An external administrator owns the final portfolios, outcomes and scoring.

Internal refinement should stop if it does not directly reduce one of these
remaining scaffolds.
