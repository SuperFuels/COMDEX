## Inferring interventions

For candidate change \(a\), AION compares:

\[
\Delta_{\mathrm{source}}(a)
=
\mathbb{1}\!\left[
H_{\mathrm{candidate}}\neq H_{\mathrm{baseline}}
\right]
\]

and

\[
\Delta_{\mathrm{outcome}}(a)
=
\mathbb{1}\!\left[
\mathbf{T}_{\mathrm{candidate}}
\neq
\mathbf{T}_{\mathrm{baseline}}
\right],
\]

where \(H\) is the source hash and \(\mathbf{T}\) is the independent property
test vector. A candidate is treated as an intervention only when the artifact
changed and the independently observed outcome changed.

Across every outcome-changing candidate, intervention inference accuracy was
100%.

## Fresh-process execution

Every candidate is compiled directly from source into a fresh namespace inside
a separate Python process. This avoids module and bytecode caching.

This control was added after an initial diagnostic run revealed that rapid
sandbox rewrites could execute stale cached bytecode. The contaminated run
failed closed and produced no promotion. Direct fresh compilation removed this
execution confounder.

The external process uses two authority layers:

- public property tests for challenger construction;
- hidden property tests opened once for the selected candidate.

No patch is retained unless both layers pass.

## Adaptive-MDL repair invention

Atomic repair candidates are tried under a cost:

\[
\mathcal{C}(p)
=
L(p)
+\lambda_r R(p)
+\lambda_e E(p),
\]

where \(L\) is patch description length, \(R\) is declared execution risk and
\(E\) is measured test cost.

If no atomic repair passes, AION recursively composes atoms in increasing
description/risk cost. Search stops on verified success or exhaustion of the
bounded atom set.

The serialization project required two independent changes:

```text
restore Unicode preservation
+ restore canonical key ordering
```

No atomic candidate passed both public properties. The two-edit composition
passed public and hidden deterministic roundtrip tests and was retained.
