\section{The General Apprenticeship Executor}
\label{sec:aion-general-apprenticeship-executor}

The General Apprenticeship Executor is complete, internally promoted,
integrated with the Autonomous General Apprentice Kernel, and active within
AION's persistent cognitive runtime.  The retained champion is
\begin{center}
\small\path{procedure_general_apprenticeship_executor_v1}.
\end{center}
Unlike the preceding control-plane promotion, this stage carries an authorized
learning contract through real resource discovery, exercise construction,
execution, criticism, transfer, restart-separated retention, and curriculum
feedback.  Its complete operating chain is
\begin{equation}
\begin{aligned}
\text{broad objective}
&\rightarrow \text{discover resources}
\rightarrow \text{invent exercises}
\rightarrow \text{execute} \\
&\rightarrow \text{diagnose failures}
\rightarrow \text{improve}
\rightarrow \text{transfer} \\
&\rightarrow \text{retest after restart}
\rightarrow \text{retain}.
\end{aligned}
\label{eq:general-apprenticeship-executor-chain}
\end{equation}

The immutable mission used for the first end-to-end apprenticeship was:
\begin{quote}
Learn how to preserve service continuity when unfamiliar persisted state
becomes empty or malformed, then transfer the verified method to a
qualitatively different transactional application.
\end{quote}

\subsection{Resource and Failure Discovery}
\label{subsec:apprenticeship-resource-discovery}

The executor operated on a real historical COMDEX repository transition.  The
public failure signal, parent commit, and parent source were available to the
learner.  The later human implementation was withheld from the proposal
mechanism until after AION had selected and independently tested its private
candidate.  All work occurred in disposable local Git clones; no live source
file was modified.

From the parent implementation, AION discovered four applicable authorities:
Git history, the Python interpreter, the Pydantic runtime, and fresh pytest
subprocesses.  It inferred five state distinctions required to explain the
observed persistence boundary:
\begin{equation}
\mathcal{S}=\{
\mathrm{missing},\mathrm{valid},\mathrm{empty},
\mathrm{malformed},\mathrm{quarantined}
\}.
\label{eq:invented-persistent-states}
\end{equation}
These distinctions were not supplied as the expected output vocabulary.
They were induced from the source operations, type boundary, and natural
failure signal.

\subsection{Self-Generated Curriculum and Executable Falsification}
\label{subsec:apprenticeship-self-generated-exercises}

AION constructed six exercises with monotonically increasing difficulty:
missing state, valid state, empty state, malformed state, exclusion of
quarantined state from active enumeration, and independent handling of
multiple corrupt artifacts.  The final exercise required both corrupt payloads
to remain recoverable while neither remained visible as active state.

The private repair proposed the abstract method
\begin{quote}
validate, quarantine, preserve evidence, then return absence.
\end{quote}
The original historical checkout failed the invented property test.  The
private challenger passed the public exercises, Python compilation, and a
held-out repository test revealed only after candidate selection.  The later
human outcome was then consulted as an independent semantic comparison.  The
challenger was accepted on behavioural equivalence---optional absence, empty
state handling, and evidence-preserving quarantine---rather than textual source
equality.

Before execution, the critic rejected six malicious proposal classes:
dynamic evaluation, arbitrary execution, subprocess use, network access,
destructive deletion, and path escape.  Security rejection remained absolute;
functional plausibility could not override a failed audit.

\subsection{Failure-Driven Revision}
\label{subsec:apprenticeship-failure-driven-revision}

The promoted result followed two rejected attempts.  First, the security critic
incorrectly attributed an existing explicit delete operation in the parent
repository to the proposed change.  The critic was revised to attribute risk
to the candidate delta while the complete candidate remained subject to
executable behavioural verification.  Second, the transfer experiment exposed
an unclosed seed transaction.  The private experiment was corrected by
committing its seed state before applying the intervention.

Neither failed challenger was promoted.  Both remain in outcome history.  The
result therefore demonstrates the intended metacognitive repair chain:
\begin{equation}
\text{failure}
\rightarrow \text{layer attribution}
\rightarrow \text{private revision}
\rightarrow \text{independent retest}
\rightarrow \text{retained method}.
\label{eq:apprenticeship-private-revision}
\end{equation}

\subsection{Source-Disjoint Transfer and Restart Retention}
\label{subsec:apprenticeship-transfer-retention}

The verified method was transferred from a file-backed Python repository to an
unfamiliar in-memory SQLite application containing active and quarantine
relations.  A matched cold search evaluated three strategies:
\begin{enumerate}
    \item ignore invalid records;
    \item delete invalid records; and
    \item validate and quarantine while preserving evidence.
\end{enumerate}
Only the third strategy satisfied both continuity and evidence-preservation
requirements.  The cold learner therefore required three attempts, whereas
the retained apprentice selected the successful method on its first attempt.
The environmental-attempt reduction was
\begin{equation}
1-\frac{N_{\mathrm{retained}}}{N_{\mathrm{cold}}}
=1-\frac{1}{3}=66.67\%.
\label{eq:apprenticeship-attempt-reduction}
\end{equation}

After persistent state was reconstructed, the same abstract method was applied
to a renamed telemetry-packet application.  It passed without replaying the
repository source and without a relearning action.  The retained state contains
the abstract method and provenance hashes, not the historical source solution.

\subsection{Closed-Loop Curriculum Authority}
\label{subsec:closed-loop-curriculum-authority}

The successful outcome was returned to the Autonomous General Apprentice as a
verified \path{transactional_data_integrity} receipt.  The procedure was also
registered as a reusable, proposal-only executor contract.  Registration
requires an existing verified receipt, an owner-approved execution authority,
and an explicit proposal-only flag.  An executor cannot acquire truth authority,
change the terminal mission, or promote itself.

This integration exposed and corrected a weakness in the earlier curriculum
metric.  Artifact density could reach its maximum because many reports
mentioned transfer, continual learning, or tool invention.  Document volume is
not executed mastery.  Let $E_g$ be the verified curriculum receipts for gate
$g$, $U_g$ the distinct outcome authorities, $T_g$ the distinct transfer
families, and $R_g$ the retained receipts.  Closed-loop support is now
\begin{equation}
\begin{aligned}
C_g={}&0.30\min\!\left(1,\frac{|E_g|}{3}\right)
+0.25\min\!\left(1,\frac{|U_g|}{2}\right) \\
&+0.25\min\!\left(1,\frac{|T_g|}{2}\right)
+0.20\min\!\left(1,\frac{|R_g|}{2}\right).
\end{aligned}
\label{eq:closed-loop-apprenticeship-support}
\end{equation}
Reports may supply proposal context, but only independently executed outcomes,
transfer, and retention increase $C_g$.  At this snapshot, open-ended learning
has one verified authority, one transfer family, and one retained receipt,
giving $C_g=0.45$.  The remaining nine gates remain at zero closed-loop support.
This prevents AION from mistaking extensive documentation for completed
competence.

\subsection{Persistent Live Operation}
\label{subsec:general-apprenticeship-live-operation}

At the recorded snapshot, the canonical cognitive runtime, real-outcome
learner, and General Apprentice supervisor were active.  Arena~v15 remained
active at five of twelve required cycles and 4.03 of 24 required elapsed hours.
The apprentice had already committed its next prediction.  A later Arena
outcome will be eligible to close that generation only if it occurs after the
commitment cursor; prior evidence cannot be reused after the prediction is
known.  The resulting receipt will update closed-loop support and cause the
curriculum to select the next under-tested capability.

\subsection{Claim Boundary and Next Gate}
\label{subsec:general-apprenticeship-executor-boundary}

This is the first complete reusable apprenticeship beneath the persistent
control plane.  It is not yet arbitrary subject mastery or AGI.  The historical
target, generic corruption representation, exercise semantics, security policy,
and verification harness remain engineered.  Transfer crossed repository
recovery and transactional data integrity, not two entirely unrelated
intellectual disciplines.  Retention was process-separated rather than
month-separated.

The next decisive gate is repeated autonomous apprenticeship across multiple
unfamiliar objectives and independently revealing authorities.  AION must
select an existing executor when its verified contract applies, invent a new
executor when no retained contract is adequate, demonstrate positive
cross-subject transfer, and preserve competence over elapsed operation without
returning to a hand-authored workflow for every lesson.
