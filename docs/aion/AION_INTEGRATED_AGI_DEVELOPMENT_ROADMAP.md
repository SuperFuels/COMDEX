# AION Integrated Intelligence Development Roadmap

## Strategic conclusion

AION has a credible governed learning architecture, but its demonstrated
competence is uneven. Experimental causal learning, software falsification,
provenance, abstention and restart-persistent skill memory are ahead of broad
language understanding, concept association, durable semantic memory, natural
multimodal grounding and social intelligence.

The programme must therefore advance through two equal critical paths:

1. **Experimental intelligence:** diagnose, intervene, falsify, repair, invent
   tools and learn from independent outcomes.
2. **Knowledge and concept intelligence:** read, perceive, form concepts,
   associate and recombine them, preserve them with provenance, and reuse them
   in unfamiliar reasoning and creation.

Neither path alone constitutes general intelligence. Their integration is the
central research objective.

## Non-negotiable architecture

The following boundaries remain locked:

- neural and language models produce proposals, not accepted truth;
- reported claims remain distinct from verified knowledge;
- source provenance survives retrieval, consolidation and revision;
- execution, proof, independent evidence, observed outcomes or human judgment
  provide task-appropriate authority;
- every learned component is replaceable and reversible;
- failed challengers cannot modify the retained champion;
- uncertainty must drive information gathering, clarification or abstention;
- CAU remains the promotion authority;
- provider removal must leave the governed symbolic path operational.

## Critical Path A — Open experimental and software intelligence

### A1. Open patch and falsification-test invention

Remove all task-specific repair menus and official-patch access. From only the
issue, repository and permitted tools, AION must:

- localize candidate files and symbols without a target hint;
- generate exact multi-file transformations using a constrained edit
  representation;
- invent tests and security properties capable of rejecting wrong patches;
- use static checks, sandbox outcomes and verifier criticism;
- retrieve abstract repair motifs, never concrete held-out solutions;
- revise or abstain under a fixed search budget.

The next representation study must compare:

- unified diffs;
- syntax-tree edit programs;
- typed edit DSLs;
- constrained multi-step source transformations.

Promotion requires reproducible success across at least ten hidden failures,
five unrelated repositories and three programming languages.

Current implementation checkpoint: the governed semantic router preserved
100\% repair success and reduced attempts relative to never-memory, but it only
tied always-documentation and was rejected. Executable model-generated tests
falsified all three original public bugs, but only one repaired checkout passed
both functional and adversarial programs; trace-only revision did not improve
that initial result. The successor separated execution grounding from property
invention: three exact-source-attested adapters were acquired, and adapter-
grounded functional/adversarial programs then achieved original-fail,
candidate-pass and adversarial-pass behavior on all three repositories. The
remaining gate is scale and independence: explicit malicious-candidate
rejection, five repositories, three languages, repeated seeds, conditional
routing and external hidden administration.

The adversarial successor has now closed the first and part of the third items
on the current cohort: 18/18 explicit malicious mutations and 3/3 plausible
wrong repairs were rejected, while all three repositories preserved the exact
original-fail/candidate-pass/adversarial-pass distinction under three fresh
process seeds. Five-repository/three-language breadth, genuinely conditional
routing and external hidden administration remain open.

Language acquisition has now reached a bounded three-language contract. Five
execution targets spanning Python, JavaScript and TypeScript passed, including
three-seed Node/TypeScript stability and four rejected language-specific
counterexamples. Because the JavaScript and Photon TypeScript targets share the
COMDEX Git authority, this represents four independent repository families;

The construction successor added bounded Rust and SQL competence. AION wrote

open-schema transactional SQL ledger, rejected unsafe language constructs, and
selected the independently optimal technology across six project requirement
profiles. This demonstrates program construction and consequence-scored choice,

verified rollback, overflow handling and eight-thread value conservation. Its

longer the primary development bottleneck. A checksum-bound external-evaluator
handoff is frozen, but independent hidden administration remains deliberately
open and cannot be self-certified.

### A2. Programming-language acquisition

AION should learn how to acquire languages rather than claim static knowledge
of every language. Given documentation, examples, toolchain commands and
development tests for an unfamiliar language, competence must be demonstrated
by:

- parsing structures, types, control flow and project layout;
- writing and editing valid idiomatic programs;
- compiling, linting and executing in a sandbox;
- inventing falsifying tests;
- transferring an abstract repair or design pattern from another language;
- abstaining outside learned competence.

### A3. Security as a universal promotion gate

Every generated patch and tool must face:

- injection, authorization and trust-boundary checks;
- path traversal and unsafe file-handling probes;
- unsafe deserialization and command-construction checks;
- secret and credential handling checks;
- dependency and supply-chain review;
- least-privilege execution;
- rejection of changes that disable verification or weaken security defaults.

Functional success cannot compensate for a security regression.

### A4. Real delayed software outcomes

Run long projects against unfamiliar repositories and independently generated
outcomes:

- CI results;
- hidden regression and security tests;
- delayed failures;
- human code review;
- later dependency or environment changes.

Failures must be attributed to perception, localization, representation,
causal diagnosis, patch generation, test quality, execution, security or goal
ambiguity. Each class receives a separate private challenger queue.

## Critical Path B — General knowledge, concepts and durable memory

### B1. Long-document and book comprehension

Given an arbitrary long document or book, AION must construct:

- structural outline;
- entities, definitions, events and timelines;
- claims, evidence, assumptions, arguments and counterarguments;
- examples, implications and unresolved questions;
- exact source spans and hashes.

It must distinguish:

- what the author reports;
- what the author argues;
- what AION infers;
- what independent evidence verifies;
- what remains uncertain or contradicted.

### B2. Concept formation, association and composition

AION must learn reusable attributes, objects, relations, events and
affordances—not merely store phrases. Evaluation must test systematic
recombination:

- known attribute + new object;
- known relation + unfamiliar entities;
- concrete concept reused abstractly;
- one structure transferred into an unrelated domain;
- polysemy separated when the same word has incompatible meanings.

The target is generative reuse such as learning colour and object concepts,
then correctly understanding or producing unseen combinations without storing
each combination independently.

### B3. Durable semantic, episodic and procedural memory

Memory must include:

- semantic concepts and relations;
- episodic observations and outcomes;
- procedural skills and tool contracts;
- provenance, confidence and time;
- supporting and contradicting evidence;
- revision, supersession and revival history.

Delayed tests after process restart must require AION to retrieve, compose and
revise earlier knowledge in new tasks. Keyword retrieval alone is insufficient.

### B4. Evaluation and transfer use

AION must:

- answer questions from previously ingested material;
- teach back an argument at several levels of detail;
- compare multiple sources;
- identify bias, missing evidence and internal inconsistency;
- use earlier concepts in planning, explanation and creative production;
- state when memory is insufficient and seek evidence.

## Critical Path C — Perception, commonsense and creative cognition

### C1. Natural multimodal grounding

Connect language and concepts to natural images, diagrams, tables, audio,
video, software state and live sensor streams. Tests must include:

- cross-modal identity and reference;
- temporal event binding;
- conflicting modalities;
- missing or unreliable sensors;
- affordances and physical consequences;
- explicit abstention when alignment is uncertain.

### C2. Commonsense and social intelligence

Use human-authored situations involving:

- physical expectations;
- agency, goals and competing incentives;
- belief and perspective differences;
- emotion and interpersonal consequences;
- consent, norms and cultural variation;
- ambiguity and misunderstanding.

The action policy is not restricted to answering. It may ask, present
alternatives, seek approval or abstain. Multiple independent judges and
calibrated disagreement replace fabricated single gold labels.

### C3. Creative synthesis

Require new stories, explanations, designs, hypotheses and plans that:

- recombine retained concepts systematically;
- satisfy explicit constraints;
- remain consistent across long structure;
- distinguish factual grounding from invention;
- receive independent human evaluation where execution cannot define quality.

## Critical Path D — Metacognition and continual self-improvement

### D1. First-class epistemic state

Every track must expose:

- known and verified;
- reported but unverified;
- suspected;
- contradicted;
- unexplained;
- outside the current representation;
- requires clarification;
- requires measurement or experiment.

This state determines search, experiment, tool selection, human escalation and
abstention.

### D2. Universal counterexample generation

Every proposed patch, concept, schema, causal theory, tool, plan or memory
revision must face active attempts to falsify it before promotion.

### D3. Long-lived continual arena

Run thousands of changing human-authored and procedurally generated tasks over
weeks or months. AION's measured weakness map selects private curricula, while
separate evaluators retain authority. Required measurements include:

- forward transfer;
- backward retention;
- weakest-family performance;
- calibration;
- complexity growth;
- retirement and revival;
- compute and information cost;
- component replacement after restart.

## Critical Path E — Substrates and consolidation

Compare replaceable 500M--3B and stronger pretrained substrates under identical
HexCore interfaces, information budgets and authority boundaries. Measure:

- long-document comprehension;
- concept extraction and composition;
- code localization and edit generation;
- multimodal proposals;
- planning and clarification;
- latency and compute cost.

Train AION-native proposal heads only from provenance-bearing, independently
verified trajectories. Consolidation improves proposal speed and quality; it
does not transfer acceptance authority into neural weights.

## Critical Path F — Independent evaluation

Independent evaluators must own:

- hidden tasks and solutions;
- sealed repositories and tests;
- books, documents and delayed retention questions;
- multimodal and social cohorts;
- scoring and answer reveal;
- matched budgets for AION, frontier agents, open systems and humans.

Required ablations:

- complete AION;
- HexCore disabled;
- memory disabled;
- tools disabled;
- neural substrate disabled;
- accumulated learning disabled.

No internal result may authorize the final capability claim.

## Canonical cognitive runtime integration

The earlier goal, heartbeat, Tessaris, Theta, HexCore and Arena loops are now
joined by `canonical_cognitive_runtime.py`. The runtime selects the
highest-priority eligible goal, opens governed context, investigates, constructs
candidate learning context, plans, commits before action, executes through a
replaceable adapter, binds immediate or delayed outcomes, criticises failures,
routes them to the knowledge/world/skill learner, evaluates private challengers
and retains verified improvements. Every stage is checkpointed atomically and
hash-ledgered. Ambiguous in-flight actions are never silently repeated after
restart.

This closes runtime unification as a missing architectural component. The next
work is not another abstract loop; it is expanding verified adapters and
outcome authorities, operating the canonical loop continuously across diverse
goals, and demonstrating cumulative cross-domain mastery.
