# AION HexCore — Open Experiment-Program Arena v4

## Status

Arena v4 is promoted internally as:

`procedure_open_experiment_program_arena_v4_7b66f2843ca9`

Parent:

`procedure_long_running_changing_project_arena_v3_f948c2272b31`

Arena v4 removes the supplied menu of complete project actions. AION instead
constructs typed experiment programs from smaller safe primitives, actively
searches for observations that falsify competing programs, executes the
selected program through governed adapters, transfers retained motifs to
renamed projects and abstains when the complete grammar is inadequate.

## Research question

Can verified experience teach AION not merely which existing action to choose,
but how to compose a new executable action program while preserving:

- outcome authority;
- active falsification;
- minimum real-world intervention cost;
- transfer to source-disjoint names;
- pre-execution security;
- restart persistence; and
- explicit criticism of the available representation?

## Architecture

```text
broad outcome contract
  -> safe typed primitive grammar
  -> enumerate single- and multi-primitive programs
  -> select maximum-disagreement experiment
  -> commit query before outcome reveal
  -> eliminate programs by counterexample
  -> select minimum-complexity survivor
  -> sealed post-selection verification
  -> governed real adapter execution
  -> retain abstract motif or abstain
  -> CAU promotion
```

The outcome queried during synthesis is controlled by the environment, not by
the candidate program. Post-selection cases remain withheld until the program
has been selected.

## Program grammars

The experiment compiler operates over four typed grammars:

| Surface | Representative primitives | Invented role |
|---|---|---|
| Software | first-by-key, last-by-key, key ordering | event normalization pipeline |
| Database | basic table, uniqueness, foreign-key constraint | executable integrity schema |
| Sensor | raw, mean window, median window, clipping, lag | robust observation pipeline |
| Documents | direct dependents, transitive closure, global invalidation | revision-propagation procedure |

Complete solutions were not enumerated as the action contract. Candidate
programs were composed from these primitives. The canonicalized software
repair required a genuine two-stage program:

```text
last_by_key -> sort_key
```

The primitive vocabularies and interpreters remain engineered and are recorded
as an explicit boundary.

## Active falsification

For each synthesis world, AION maintained all programs consistent with the
observations collected so far. It selected the next experiment by minimizing
the largest surviving outcome partition, equivalent to seeking the case with
the greatest candidate disagreement.

The development cohort generated 33 concrete program counterexamples. The OOD
criticism path generated an additional counterexample. No candidate was
accepted merely because it fit an initial demonstration.

## Governed negative result

The first v4 implementation recovered and executed every correct program, but
the retained-motif path required exactly as many environment queries as cold
synthesis. It therefore failed both the transfer-efficiency and active-
falsification promotion requirements.

The challenger was not promoted.

The corrected protocol introduced dual accounting:

- retained motifs receive one real environment confirmation;
- the program is selected before a disjoint sealed property suite is revealed;
- sealed verification does not masquerade as a free environmental
  intervention; and
- a failed confirmation or sealed property causes fallback or rejection.

This made the transfer claim dependent on fewer real interventions without
weakening independent verification.

## Real adapter execution

Synthesized programs were lowered into the same independently executed Arena
v3 adapters:

- Python subprocess behavior;
- SQLite constraint behavior;
- delayed CSV sensor outcomes; and
- disk-backed dependency-manifest verification.

A syntactically valid program without a verified lowering contract was not
executable and could not be promoted.

## OOD grammar criticism

The OOD sensor world used a nonlinear sine response not expressible by the
retained raw, smoothing, clipping or lag grammar. The previous median-filter
motif failed confirmation, active synthesis failed the withheld property
suite, and AION retained no program.

The resulting disposition was abstention, with zero unsafe forced program.
This establishes criticism of the complete available grammar, not invention of
an unrestricted new primitive.

## Security and authority

Programs requesting dynamic execution, network access, filesystem writing or
authority override were not members of any permitted grammar. All four were
rejected before execution.

Neural or language proposals cannot:

- add a primitive to the authority grammar;
- decide an outcome;
- reveal sealed properties;
- lower a program into an unverified adapter;
- write the live repository; or
- approve their own promotion.

## Persistence

The eight learned family/role motifs, program hashes, verification authority,
generation record and champion survived complete runtime reconstruction with
zero program relearning.

## What this advances

Arena v3 learned when to reuse complete verified repairs. Arena v4 moves one
level deeper:

```text
verified outcomes
  -> reusable primitive motifs
  -> newly composed experiment program
  -> active counterexample search
  -> fewer real interventions
  -> governed execution
  -> retained transferable program
```

This is a bounded form of learning how to construct an action, rather than only
learning which named action to select.

## Claim boundary

Arena v4 is not unrestricted invention. The following remain engineered:

- primitive vocabularies;
- type system;
- candidate-program depth;
- interpreters and adapter lowerings;
- outcome cases and sealed evaluator;
- project families; and
- internal administration.

The correct claim is governed open experiment-program composition within four
typed grammars, with active falsification, transfer, OOD abstention and real
adapter execution. It is not AGI, autonomous unrestricted tool creation or
external certification.

## Next decisive frontier

The next programme should attack the remaining scaffolds in this order:

1. **Primitive invention under execution:** detect systematic residuals that
   no grammar expresses; synthesize a private primitive implementation; test
   safety, algebraic properties and transfer before extending the grammar.
2. **Independent outcomes:** connect projects to tests, observations and human
   judgments maintained outside the development process.
3. **Natural multimodal projects:** ground images, diagrams, tables and text in
   one changing project with deliberate cross-modal contradiction.
4. **Human commonsense, social and creative authority:** use several human
   judges, retain disagreement and prohibit a synthetic single gold label.
5. **Long continual arena:** operate across hours or days and many rolling
   generations with forgetting, calibration, complexity and retirement/revival
   measurements.
6. **Stronger substrate tournament:** compare replaceable proposal models under
   identical evidence, tools, compute, outcomes and CAU boundaries.
7. **External administration:** freeze commitments and let an independent
   evaluator own the final tasks, outcomes and scoring.

Further internal grammar exercises should be rejected unless they directly
remove one of these boundaries.
