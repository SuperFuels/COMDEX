\section{AION Native Intelligence in the Unified Mobile Application}
\label{sec:pilot-unified-mobile-aion-native}

The unified phone composer is now connected to the customer's governed mother brain.  It is no
longer a visual placeholder and does not call a model provider directly.  A private request travels
from the signed phone surface into AION, which identifies the person, resolves the intent, applies
policy, chooses a capability or computational provider, verifies any executable result and returns
an honest state to Pilot.

\subsection{Default Provider-independent Route}

The default mode is \texttt{native}.  Its ordered route is deterministic local capability, existing
AION knowledge and memory, a compatible local model, bounded public evidence and finally an honest
limitation.  Gemini and premium providers are not attempted in this mode.  Core tasks,
communication drafting and public-evidence research therefore remain useful when every paid model
key is removed.

Two optional ceilings may be selected explicitly.  \emph{AION + Gemini} permits user-key Gemini
synthesis and separately configured search grounding only after Native routes.  \emph{Pilot Boost}
may use a connected premium provider only after Native and permitted Gemini routes fail.  These
modes are maximum permissions, not forced providers; deterministic and local capability always
remain first.

\subsection{Signed Phone Boundary}

The mother grants separate \texttt{intelligence.read}, \texttt{intelligence.use} and
\texttt{intelligence.configure} scopes.  Requests are signed by the phone's Ed25519 possession key
and bound to its certificate, lease and private persona.  Provider keys, local secret paths and
credentials never enter the response.  Changing to a cloud-capable route requires a visible phone
confirmation explaining that permitted context may leave the customer-controlled machine.

The interface displays the current route label and presents Native, Gemini and Boost as explicit
choices.  Responses are labelled \emph{AION Local}, \emph{AION + live public evidence} or
\emph{Pilot Boost}.  Execution receipts are distinguished from plans and research; absence of a
receipt is shown as no external action claimed.

\subsection{Conversation and Evidence Semantics}

Typed requests use the same private-phone conversation channel as existing Pilot intelligence, so
follow-ups can reuse the appropriate private objective without entering shared-TV memory.  Research
continues to bind citations to retrieved evidence outside the model, reject invented source URLs
and distinguish model interpretation from verified evidence.  A model response remains a proposal;
it does not independently obtain business, account or device authority.

Focused routing and mobile tests verify that Native is the default without paid providers, public
evidence remains useful, Gemini follows local routes, Boost follows both, provider settings contain
no keys and the phone composer uses the signed mother endpoint.  The optimized Next.js production
build compiles successfully.  Automated verification made no provider call and executed no external
action.
