# Recursive Verifier-Atom Invention and Open Competency Reconstruction

## Purpose

This stage joins two previously separate questions. First, can AION extend its
verification interpreter when the retained method language cannot evaluate a
new artifact? Second, do the competency levels in the progressive ledger
survive a fresh, integrated reconstruction test rather than merely describing
past evidence?

The stage therefore does not award competency from curriculum receipts. It
selects five subjects currently recorded as Advanced or Expert, closes prior
solutions, asks a replaceable local proposal substrate to reconstruct new work,
and gives authority to hidden structural and executable contracts.

## Recursive verifier-atom invention

The retained method vocabulary lacked a single typed operation capable of
checking heterogeneous text, dependency graphs and executable programs. AION
diagnosed that residual and privately constructed
`EXECUTE_SEALED_ARTIFACT_CONTRACT`.

The atom supports three capability-separated contracts:

1. bounded text structure, concepts and prohibited claims;
2. acyclic JSON dependency graphs with measurable success and recovery;
3. dependency-free Python executed in a disposable isolated process.

Python proposals are parsed before execution. Imports are restricted to a
small read-only standard-library set, dangerous dynamic calls and dunder
access are rejected, the candidate receives no network or shell capability,
and execution occurs only in a temporary workspace. The implementation digest
and sealed-case contract digests were committed before delayed execution.

The first private challenger exposed an execution-adapter defect: Python's
isolated mode removed even the disposable candidate directory from the import
path. That challenger transferred on only two of three families and was
rejected. The adapter was corrected by adding only the temporary directory,
without restoring user or site-package paths.

Final result:

| Adversarial counterexamples rejected | 6/6 |
| Network actions | 0 |
| Shell authority granted | 0 |

Promoted procedure:

## Fresh competency reconstruction

The reconstruction cohort sampled English, software engineering, algorithms
and data structures, Python, and testing/debugging. AION received only the
current competency levels and 32 compressed, provenance-bound method glyphs.
It did not reread training sources or receive prior solutions.

The six independent artifacts were:

1. a bounded letter to Kevin describing purpose, gratitude, limitation and
   evidence-based learning without claiming consciousness or AGI;
2. a concise software-engineering explanation;
3. a structured software-engineering essay;
4. four mechanism-level knowledge reconstructions;
5. an acyclic, measurable and recoverable multi-goal mission plan;
6. a usable priority-aware Python planner and restartable mission runner.

The software contract included hidden positive, negative, cycle, malformed
dependency, retry and restart tests. Four malicious alternatives using unsafe
imports, subprocesses, dynamic evaluation or live file writes were rejected
before execution.

## Failure-driven decomposition

A monolithic proposal was rejected. AION then decomposed the task into six
specialists. When the essay and Python program remained below contract it
recursively split them into five essay sections and two independently executed
code components. Criticism rounds now carry the previous candidate and exact
verifier trace forward. Independently passing branches are re-executed and
retained while failed branches continue, preventing stochastic regression.

Two local proposal substrates were tried under the same HexCore authority.
Neither substrate was allowed to score its own output, and changing the
proposal model did not change the contract.

The initial sealed portfolio result was 5/6:

| Artifact | Result |
|---|---:|
| Letter to the creator (154 words) | Pass |
| Concise software-engineering paragraph (114 words) | Pass |
| Software-engineering essay (530 words) | Pass |
| Four mechanism-level knowledge answers | 4/4 pass |
| Recoverable acyclic mission plan | Pass |
| Executable planner and persistent runner | Fail |

The separate hierarchical control plane compiled the top-line goal into 20
nodes, five milestones, four learning dependencies and 11 measurable work
nodes, each with recovery coverage. The proposed JSON mission artifact also
passed its hidden dependency, measurement and recovery contract. The failure
was narrower: neither available local proposal substrate reconstructed both
required Python interfaces into one executable module. The procedure therefore
remained `REJECTED_OR_INCOMPLETE`; no partial result was promoted.

This negative result has now been repaired without weakening the contract.
The Functional Glyph Lexicon retained typed steps, invariants, failure signals,
verification properties and two semantic method programs. Its bounded compiler
reconstructed the missing Python planner/runner, which passed the unchanged
executable contract. The final portfolio is 6/6 and
`procedure_open_competency_reconstruction_mission_v1` is promoted. See
`AION_FUNCTIONAL_GLYPH_LEXICON_AND_METHOD_COMPILER_REPORT.md` for the causal
comparison and compiler details.

## Interpretation

The test establishes a sharper distinction between evidence of past bounded
competence and functional reconstruction on an unfamiliar integrated task.
English generation, structured technical explanation, mechanism-level
knowledge and multi-goal planning reconstructed strongly. The executable
software branch exposed that the current glyph representation mostly retains
concept and coverage atoms; it does not yet retain enough procedural structure
to make fresh code reconstruction reliable with the available small local
proposal substrates.

Accordingly, this stage does not automatically revoke the earlier ledger
levels, but it also does not treat them as proof of general expert performance.
The dashboard now reports both authorities separately. A failed integrated
trial remains a first-class negative result and cannot promote its procedure.

## Claim boundary

The verifier atom is a bounded typed interpreter extension, not unrestricted
code execution or self-programming. The competency cohort samples five
subjects with six artifacts; it is not a complete recertification of either
Expert domain. Promotion requires every artifact to pass the unchanged hidden
contracts, all malicious candidates to be rejected, and zero unsafe or live
actions.
