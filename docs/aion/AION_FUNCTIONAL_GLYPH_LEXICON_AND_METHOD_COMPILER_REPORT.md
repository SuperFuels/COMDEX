# Functional Glyph Lexicon and Executable Method Reconstruction

## Problem

The earlier glyph store compressed verified evidence effectively but retained
many subskills as names and coverage markers. In the first open competency
audit, AION could explain software engineering, answer algorithm questions and
construct a hierarchical mission, yet could not reliably recreate one usable
Python module. The result remained fail-closed at 5/6.

Trace analysis identified two distinct defects:

1. retained glyphs named concepts such as graphs and topological ordering but
   lacked reconstructable procedures, invariants, failure signatures and
   verification properties;
2. the criticism bridge sent only `executable_contract_failed` to the proposal
   substrate and discarded the diagnostic assertion produced by the verifier.

## Functional Glyph Lexicon

The new lexicon is a content-addressed, typed graph rather than a flat topic
index. Its node vocabulary is lexical sense, concept, procedure, invariant,
failure, verifier, transfer abstraction and provenance anchor.

Typed edges include `requires`, `uses`, `must_preserve`, `fails_as`,
`verified_by`, `transfers_to`, `supported_by`, `composes_with`,
`language_hosts`, `represents` and `diagnosed_by`.

Every procedure carries purpose, inputs, preconditions, ordered steps,
invariants, failure signals, verification properties and transfer domains.
Evidence remains outside active memory and is referenced by immutable hash.

## Typed executable method programs

Human-readable procedural facets are paired with a compact semantic program.
The planning capsule contains eight operators covering identifier and
dependency validation, dependency readiness, priority ordering,
capability-gap insertion, identifier emission, completed-state advancement and
cycle rejection. The mission-runner capsule contains seven operators covering
current-task selection, outcome matching, success advancement, failure retry,
snapshot, restoration and completion.

The compiler accepts only complete known operator sets. Missing, unknown or
authority-expanding operators cause abstention. It reconstructs a
dependency-free Python skill without reopening evidence or retrieving stored
Python source.

## Repair of the competency reconstruction failure

The original sealed contract was not weakened. It still required exact
dependency/priority ordering, capability-gap insertion, malformed graph
rejection, bounded retry, snapshot/reconstruction and no completed-task replay.

The functional compiler generated a candidate from the two retained method
programs. HexCore ran the unchanged disposable-process contract. The portfolio
advanced from 5/6 to 6/6:

| Artifact | Result |
|---|---:|
| Creator letter | Pass |
| Concise software-engineering explanation | Pass |
| Software-engineering essay | Pass |
| Mechanism-level knowledge reconstruction | 4/4 |
| Recoverable mission graph | Pass |
| Executable Python planner and mission runner | Pass |

The module printed `SEALED_MISSION_EXECUTOR_PASS`; 4/4 malicious candidates
were rejected; no prior solution was exposed; no raw learning source was
reread; and no live source file was modified.

Promoted procedure: `procedure_open_competency_reconstruction_mission_v1`.

## Criticism repair

The reflection bridge now supplies bounded diagnostic fields—failure class,
return code, final stderr/stdout fragment and structural counts—instead of
collapsing executable failures into one generic token. Hidden verifier source
remains withheld. Passing branches are retained while only failed branches are
reconsidered.

## Interpretation and boundary

This is causal evidence that functional memory changed behaviour: shallow
glyph names produced repeated code failure; semantic-procedural capsules plus
typed compilation passed the unchanged contract.

It is not complete Python expertise, a complete natural-language ontology or
unrestricted program synthesis. The current lexicon has two executable
procedures and 15 compiler operators. The next scale gate is autonomous
population: extract and validate many new capsules from verified trajectories,
then prove unfamiliar reconstruction across unrelated procedures, languages
and real-world action domains.
