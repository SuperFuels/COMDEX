\section{Purpose}

Phase 22E.61 adds the parallel opponent beam router and SQI collapse layer.

Phase 22E.60 generates opponent response beams for one candidate move.

Phase 22E.61 routes multiple candidate moves through that beam system, expands opponent replies into continuation beams, and collapses the candidate set by SQI risk.

\section{Architecture}

The locked route is:

\begin{verbatim}
candidate moves
  -> Phase 22E.60 opponent response beams
  -> continuation beam expansion
  -> parallel beam budget
  -> SQI collapse packet
  -> QQC router packet
  -> HexCore router packet
  -> selected candidate or rejected candidate
\end{verbatim}

\section{Parallel Beam Budget}

The kernel exposes a parallel beam budget.

The default budget is 1000 beams.

Focused tests use smaller child limits for runtime speed, but the contract records that the router is designed for a 1000-beam budget.

\section{Collapse Rule}

The router computes:

\begin{itemize}
  \item maximum opponent beam danger;
  \item minimum SQI coherence;
  \item SQI collapse risk;
  \item QQC symbolic temperature;
  \item HexCore drift.
\end{itemize}

A candidate is rejected when opponent reply risk dominates the collapse threshold.

\section{Boundary}

This phase does not post moves.

It does not call Stockfish, does not use Lichess analysis and does not use LLM move judgement.
