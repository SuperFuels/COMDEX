\label{sec:aion-phase20d-autonomy-lane-classifier-lock}

\subsection{Status}

Phase 20D locks the deterministic Autonomy Lane Classifier for AION Mission Mode / AION Pilot.

\begin{quote}
\textbf{Status: LOCKED --- deterministic classifier only. No LLM calls, no live tools, no external writes.}
\end{quote}

\subsection{Purpose}

The classifier sits between the deterministic Mission Planner and the Mission Runtime.

Planner and LLM-provided labels are advisory only. The classifier owns the final lane and execution decision.

\subsection{Lanes}

The supported lanes are:

\begin{itemize}
  \item \texttt{research}
  \item \texttt{creation}
  \item \texttt{internal\_ops}
  \item \texttt{external\_action}
  \item \texttt{financial\_action}
  \item \texttt{legal\_action}
  \item \texttt{deployment\_action}
  \item \texttt{memory\_mutation}
\end{itemize}

\subsection{Decisions}

Every step is assigned one of:

\begin{itemize}
  \item \texttt{safe\_autonomous}
  \item \texttt{checkpoint\_required}
  \item \texttt{blocked}
  \item \texttt{forbidden}
\end{itemize}

\subsection{Safety Rule}

External, financial, legal, deployment, and memory mutation actions MUST NOT be classified as \texttt{safe\_autonomous}.

Unknown actions MUST be blocked until explicitly classified.

Live/raw actions such as live WhatsApp sends, live email sends, payment capture, production deploys, raw terminal execution, and live reputation writes are forbidden.

\subsection{Phase 20D.1 --- Strict Parameter Whitelist and Atomic Batch Invalidation}

The Payload Token Guard MUST enforce strict key-level schema validation.

The classifier SHALL maintain an immutable parameter whitelist for every permitted \texttt{safe\_autonomous} action type.

A planner, LLM adapter, template, or runtime step MUST NOT be allowed to attach arbitrary parameters to a safe action.

If a mission step declares a known safe action such as \texttt{draft\_offer}, but introduces unknown keys, nested parameter blocks, live execution flags, unregistered tool payloads, or hidden execution instructions, the classifier MUST downgrade the step to \texttt{blocked} or \texttt{forbidden}.

\begin{quote}
\textbf{A safe action name is not enough. The payload shape must also be safe.}
\end{quote}

\subsection{Atomic Batch Isolation}

The batch classifier MUST operate under strict atomic enforcement.

A mission runtime MUST NOT begin executing a partial sequence if any step in the unified classifier batch resolves to \texttt{blocked} or \texttt{forbidden}.

\begin{quote}
\textbf{If one step in the mission plan is unsafe or unresolved, the runtime queue does not mount.}
\end{quote}

If any step is \texttt{blocked} or \texttt{forbidden}, the classifier MUST return:

\begin{verbatim}
batch_valid: false
runtime_mount_allowed: false
mission_runtime_state: waiting_human_review | blocked
\end{verbatim}

\subsection{Classifier Run Hash Folding}

The classifier run hash MUST be deterministic across environments.

The implementation folds individual step classifications in stable sorted order and emits a prefixed SHA-256 value.

\begin{verbatim}
classifier_run_hash: sha256:<digest>
\end{verbatim}

  \item a batch containing one forbidden step cannot mount runtime;
  \item classifier run hashes are stable and SHA-256 prefixed.
\end{itemize}
