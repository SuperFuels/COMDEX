\section{AION Phase 20N.7 --- Expiry Management and Stale Matrix Revocation}
\label{sec:aion-phase20n7-expiry-management-stale-matrix-revocation}

\subsection{Status}

Phase 20N.7 locks Expiry Management and Stale Matrix Revocation.

\begin{quote}
\textbf{Status: LOCKED --- plan, sub-plan, profile and budget matrices may expire or become stale and must be re-approved before execution continues.}
\end{quote}

\subsection{Purpose}

Phase 20R handles exact checkpoint payload approval expiry.

Phase 20N.7 handles plan-level matrix freshness.

AION MUST prevent stale mission plans, stale sub-plans, stale profile applications, and stale budget contracts from mounting into runtime execution.

\subsection{Freshness Record}

Every matrix freshness record MUST bind:

\begin{itemize}
  \item mission ID;
  \item mission run ID;
  \item matrix ID;
  \item matrix type;
  \item matrix hash;
  \item parent matrix hash where applicable;
  \item profile application hash where applicable;
  \item budget hash where applicable;
  \item issued time;
  \item TTL seconds;
  \item expiry time;
  \item revocation state;
  \item freshness record hash.
\end{itemize}

\subsection{Freshness Evaluation}

Before runtime mount, AION MUST evaluate whether the matrix is:

\begin{itemize}
  \item expired;
  \item revoked;
  \item changed;
  \item stale because parent matrix changed;
  \item stale because profile application changed;
  \item stale because budget changed.
\end{itemize}

If stale, AION MUST return:

\begin{verbatim}
runtime_mount_allowed: false
mission_state: waiting_human_review
requires_matrix_reapproval: true
\end{verbatim}

\subsection{Security Rule}

A stale plan, sub-plan, profile application or budget contract MUST NOT mount into runtime.
