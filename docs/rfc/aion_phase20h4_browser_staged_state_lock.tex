\section{AION Phase 20H.4 --- Browser Staged State Contract}
\label{sec:aion-phase20h4-browser-staged-state-contract}

\subsection{Status}

Phase 20H.4 locks the Browser Staged State Contract.

\begin{quote}
\textbf{Status: LOCKED --- browser staged states are hash-bound, expiry-bound, approval-bound, and commit-once only.}
\end{quote}

\subsection{Purpose}

Browser workers may prepare external actions, but preparation is not execution.

A staged browser state records the exact provider page, target URL, action type, payload hash, expiry timestamp, and approval requirement before the system may request user approval or commit the action.

\subsection{Staged State Lifecycle}

A browser staged state MUST use one of the following lifecycle states:

\begin{verbatim}
none
preparing
staged
waiting_approval
expired
committed
abandoned
\end{verbatim}

Only \texttt{staged} and \texttt{waiting\_approval} states MAY be considered committable.

\subsection{Staged State Contract}

Every staged browser state MUST bind:

\begin{itemize}
  \item mission ID;
  \item mission run ID;
  \item business ID;
  \item provider;
  \item browser worker ID;
  \item provider context hash;
  \item browser session hash;
  \item action type;
  \item target URL;
  \item staged payload hash;
  \item approval requirement;
  \item staged state;
  \item creation timestamp;
  \item expiry timestamp;
  \item commit count;
  \item restaging requirement;
  \item browser session staged state hash.
\end{itemize}

\subsection{Commit Assertion}

Before commit, AION MUST assert:

\begin{itemize}
  \item staged state is committable;
  \item staged state is unexpired;
  \item restaging is not required;
  \item commit count is zero;
  \item current payload hash matches staged payload hash;
  \item approval hash exists when required;
  \item approved payload hash matches staged payload hash when required.
\end{itemize}

\subsection{Expiry Rule}

If:

\begin{equation}
T_{\mathrm{now}} > T_{\mathrm{staged\_state\_expires}}
\end{equation}

the staged state MUST NOT commit.

The runtime MUST set or preserve \texttt{requires\_restaging} and request a new staged state before execution can continue.

\subsection{Payload Mutation Rule}

If:

\begin{equation}
H_{\mathrm{current\_payload}} \neq H_{\mathrm{staged\_payload}}
\end{equation}

the staged state MUST NOT commit.

\subsection{Approval Binding Rule}

If approval is required, the approval MUST bind the exact staged payload hash.

If:

\begin{equation}
H_{\mathrm{approved\_payload}} \neq H_{\mathrm{staged\_payload}}
\end{equation}

the staged state MUST NOT commit.

\subsection{Commit-Once Rule}

A staged browser state MUST commit at most once.

After commit, the state MUST transition to \texttt{committed} and increment \texttt{commit\_count}.

Any attempt to reuse the committed staged state MUST fail closed.

\subsection{Receipt}

A committed staged browser state MAY emit a staged state receipt.

The receipt MUST bind:

\begin{itemize}
  \item mission ID;
  \item mission run ID;
  \item provider;
  \item browser worker ID;
  \item action type;
  \item target URL;
  \item staged payload hash;
  \item commit assertion hash;
  \item provider response hash;
  \item committed state hash;
  \item receipt hash.
\end{itemize}
