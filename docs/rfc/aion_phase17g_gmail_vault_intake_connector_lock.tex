\subsection{Purpose}

Small businesses often already have a website form that sends enquiries to Gmail, Outlook, or another mailbox. The lowest-friction onboarding path is therefore not a fake generated mailbox. The first live path is:

\begin{quote}
Existing website form email $\rightarrow$ connected mailbox in Vault $\rightarrow$ guarded intake read $\rightarrow$ website\_intake.trigger.created $\rightarrow$ workflow ticket preview.
\end{quote}

\subsection{Locked Behaviour}

The Website Intake Installation panel MUST expose Gmail OAuth from Vault as the first email provider.

The panel MUST NOT show \texttt{home\_fixed@intake.tessaris.ai} as if it is active.

The panel MUST state that Gmail uses OAuth credentials from the Vault and MUST NOT request raw mailbox passwords.

Live email sending remains locked.

The Gmail route is a read/intake candidate only. Any draft, reply, booking, payment, escrow, external message, or chain write remains behind human review and existing side-effect guards.

\subsection{Provider Modes}

\begin{itemize}
  \item Gmail OAuth from Vault: first real email-intake path.
  \item Existing Form Webhook: web-designer/developer route.
  \item AION Generated Form / Embed: future no-code route.
  \item Hosted AION Mailbox: future optional managed/paid route.
\end{itemize}
