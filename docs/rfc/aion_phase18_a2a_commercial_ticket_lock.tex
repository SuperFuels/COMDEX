\subsection{Commercial Ticket Contract}

The locked commercial ticket contract supports safe A2A preview tickets for service work, discovery visits, quotations, proposals, and future commercial routes.

The current locked Home Fixed test vertical includes:

\begin{itemize}
  \item \texttt{plumbing\_hourly}: hourly service/callout route.
  \item \texttt{roof\_discovery}: discovery/assessment route for roof leak inspection.
\end{itemize}

The roof discovery scenario is deliberately not allowed to create a fake final quote. It returns a discovery visit proposal preview and requires inspection before final pricing.

The locked roof scenario records:

\begin{verbatim}
requested_slot: Tomorrow 11:30
available_slot: Tomorrow 13:30
unavailable_reason: 11:30 is already held for another site visit.
customer_request: Leaking pergola roof in Arboleas after rain
\end{verbatim}

\subsection{Preview API Contract}

The Phase 18 local preview API supports scenario selection by query parameter.

\begin{verbatim}
/api/local-node/aion/phase18/a2a-commercial-ticket-preview?scenario=home_fixed_roof_discovery
/api/local-node/aion/phase18/a2a-commercial-ticket-preview?scenario=plumbing_hourly
\end{verbatim}

Unknown scenarios MUST fall back safely to the plumbing hourly preview.

The API returns:

\begin{itemize}
  \item user-facing display fields for the normal UI;
  \item raw ticket identifiers and hashes for advanced trace only;
  \item route labels and pricing labels;
  \item service rules;
  \item proposal preview;
  \item availability preview;
  \item negotiation state and negotiation steps;
  \item guard envelope;
  \item deterministic ticket and route hashes.
\end{itemize}

\subsection{Frontend Behaviour}

The desktop frontend now attempts to fetch the local Phase 18 preview API from:

\begin{verbatim}
http://127.0.0.1:8080/api/local-node/aion/phase18/a2a-commercial-ticket-preview
\end{verbatim}

If the local backend is available, the ticket source changes to Local API.

If the local backend is unavailable, the panel safely falls back to the local frontend demo ticket.

The frontend includes:

\begin{itemize}
  \item API/local fallback behaviour;
  \item timeout handling to prevent permanent loading state;
  \item source status display;
  \item success note for loaded API preview;
  \item advanced technical trace;
  \item hidden raw enums in normal user UI;
  \item runtime protection against the fixed workflow slim header overlaying the A2A ticket.
\end{itemize}
