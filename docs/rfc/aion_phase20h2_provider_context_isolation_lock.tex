\section{AION Phase 20H.2 --- Provider Context Isolation and Credential Vault Scoping}
\label{sec:aion-phase20h2-provider-context-isolation-credential-vault-scoping}

\subsection{Status}

Phase 20H.2 locks provider context isolation and credential vault scoping.

\begin{quote}
\textbf{Status: LOCKED --- provider contexts are mission-scoped, provider-scoped, and credential material is never exposed to the model context.}
\end{quote}

\subsection{Purpose}

AION Pilot may interact with external providers only through isolated execution contexts.

A provider context MUST be bound to:

\begin{itemize}
  \item mission ID;
  \item mission run ID;
  \item business ID;
  \item provider;
  \item tool name;
  \item credential scope;
  \item allowed actions;
  \item context hash.
\end{itemize}

\subsection{Credential Vault Rule}

Credentials MUST be represented as vault references only.

Plaintext credentials, API keys, access tokens, refresh tokens, cookies, authorization headers, payment tokens, card numbers, or passwords MUST NOT appear inside model-visible context.

\subsection{Context Mount Rule}

Before a provider context can mount, AION MUST verify:

\begin{itemize}
  \item mission ID matches;
  \item mission run ID matches;
  \item provider matches;
  \item requested action is inside allowed actions;
  \item no secret material is exposed.
\end{itemize}

\subsection{Cross-Boundary Blocking}

AION MUST block:

\begin{itemize}
  \item cross-mission context reuse;
  \item cross-run context reuse;
  \item cross-provider context reuse;
  \item action use outside context scope;
  \item raw secret-shaped fields inside context claims;
  \item model-visible secret exposure.
\end{itemize}
