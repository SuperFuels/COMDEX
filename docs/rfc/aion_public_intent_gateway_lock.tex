\subsection{Purpose}

Phase 12A starts the public website embed and human gateway surface.

The purpose is to define a safe preview contract for website form, button, or chat submissions before any live public gateway is permitted to create a booking, live job, payment, escrow, or external message.

This phase maps human website input into an internal preview of:

\begin{itemize}
  \item \texttt{NormalizedInboundIntent},
  \item \texttt{MachineCartRequest},
  \item human-friendly quote preview,
  \item safety flags,
  \item blocked reasons,
  \item deterministic request and response hashes.
\end{itemize}

\subsection{Implemented Module}

The implementation lives in:

\begin{verbatim}
backend/modules/aion_gateway/public_intent_gateway.py
\end{verbatim}

The module exports:

\begin{itemize}

\subsection{Human Form Mapping}

Website form, button, and chat inputs are mapped to a \texttt{NormalizedInboundIntent} preview.

The normalized intent preview includes:

\begin{itemize}
  \item \texttt{intent\_type = public\_website\_service\_enquiry}
  \item \texttt{normalization\_status = preview\_only}
  \item \texttt{human\_review\_required = true}
  \item \texttt{normalized\_intent\_hash}
\end{itemize}

\subsection{Machine Cart Mapping}

The same input is mapped to a \texttt{MachineCartRequest} preview.

The machine cart preview includes:

\begin{itemize}
  \item \texttt{status = machine\_cart\_request\_preview\_only}
  \item \texttt{business\_id}
  \item \texttt{service\_key}
  \item \texttt{location}
  \item \texttt{requested\_window}
  \item \texttt{max\_fiat\_price}
  \item \texttt{currency}
  \item \texttt{human\_review\_required = true}
  \item \texttt{would\_create\_quote = false}
  \item \texttt{would\_create\_booking = false}
  \item \texttt{would\_create\_live\_job = false}
  \item \texttt{machine\_cart\_request\_hash}
\end{itemize}

\subsection{Human-Friendly Quote Preview}

The preview returns a human-readable acknowledgement:

\begin{verbatim}
status = quote_preview_requires_human_review
final_quote_created = false
live_job_created = false
payment_created = false
escrow_created = false
\end{verbatim}

This allows the public website surface to acknowledge a customer request without implying that a final quote, booking, live job, payment, or escrow has been created.

\subsection{Gateway Safety Requirements}

The public gateway preview requires the following before any live route can be considered:

\begin{itemize}
  \item tenant/business key validation,
  \item signed request validation,
  \item rate limiting,
  \item abuse protection,
  \item human review.
\end{itemize}

\subsection{Hashing}

The preview includes:

\begin{itemize}
  \item \texttt{request\_hash}
  \item \texttt{normalized\_intent\_hash}
  \item \texttt{machine\_cart\_request\_hash}
  \item \texttt{response\_hash}
  \item \texttt{summary\_hash}
\end{itemize}

The hashes are deterministic for identical input and change when the customer message or request content changes.

\subsection{Safety Boundary}

Phase 12A MUST NOT:

\begin{itemize}
  \item create a booking,
  \item create a live job,
  \item execute the Goal Engine,
  \item bypass human review,
  \item move money,
  \item move PHO,
  \item require a wallet,
  \item create a payment,
  \item create escrow,
  \item release funds,
  \item send external messages,
  \item expose an unauthenticated public write route.
\end{itemize}
