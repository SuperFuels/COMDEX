\begin{quote}
\textbf{Status: LOCKED --- AXO vocabulary, ETS feedback packet preview, score separation, trace links, AgentMap ETS preview, and safety boundaries are defined.}

\subsection{Purpose}

The purpose of this lock is to define how AION can receive, represent, and expose trust feedback without mutating live reputation, accepting autonomous score changes, or enabling booking/payment/escrow side effects.

This phase is intentionally preview-only. It prepares the trust layer that will later sit behind AgentMap, AXO readiness dashboards, job trace evaluation, evidence validation, and proof receipt verification.

\subsection{Score Separation}

Customer outcome score and system execution score are separate fields.

\begin{itemize}
  \item Customer outcome score is a customer-visible satisfaction and service quality signal.
  \item System execution score is a machine execution, evidence, trace, and policy-compliance signal.
\end{itemize}

These scores MUST NOT be merged. A good machine execution trace does not automatically mean a good customer outcome, and a good customer outcome does not automatically prove that the system followed policy.

\subsection{Trace Links}

Every ETS feedback packet preview links to:

\begin{itemize}
  \item a job trace identifier,
  \item a proof receipt identifier,
  \item one or more evidence identifiers.
\end{itemize}

This keeps ETS grounded in evidence and proof receipts instead of free-floating reputation claims.

\subsection{Safety Boundary}

The ETS layer is locked as preview-only.

It MUST NOT:

\begin{itemize}
  \item write live reputation,
  \item autonomously accept score changes,
  \item create bookings,
  \item create payments,
  \item create escrow,
  \item bypass human review.
\end{itemize}

Anti-gaming and trust rules remain unlocked in this phase, so all score exposure is informational only.
