\subsection{Locked Principle}

Completed workflow execution is not treated as business success.

An outcome is only treated as supported when it has validator-backed evidence. Evidence existence alone is insufficient. Evidence MUST be typed, sourced, verified, confidence-scored, and preserved through the canonical Goal Engine preview bundle.

\subsection{Evidence Source Contract}

The evidence source contract is implemented in:

\begin{verbatim}
backend/modules/aion/goal_engine/evidence_sources.py
\end{verbatim}

The locked schema version is:

\begin{verbatim}
aion.goal_engine.evidence_source.v1
\end{verbatim}

The first supported evidence type is:

\begin{verbatim}
manual_confirmation
\end{verbatim}

Evidence validation checks:

\begin{itemize}
  \item evidence identifier;
  \item evidence type;
  \item source or source connector;
  \item confidence range;
  \item minimum confidence threshold;
  \item verified state;
  \item support status for outcome success.
\end{itemize}

Explicit unverified evidence does not support outcome success. Low-confidence evidence does not support outcome success. Legacy manual confirmation rows without explicit verification MAY be normalised for backward compatibility, but explicit \texttt{verified=false} MUST remain blocked.

\subsection{Boardroom Visibility}

The Boardroom evidence panel now renders:

\begin{itemize}
  \item supported success count;
  \item blocked outcome count;
  \item missing evidence warning;
  \item validator evidence rows;
  \item evidence freshness;
  \item evidence provenance;
  \item source connector;
  \item source reference;
  \item confidence;
  \item verified state.
\end{itemize}

The Boardroom therefore answers:

\begin{quote}
What evidence supports this outcome, where did it come from, how fresh is it, how confident is it, and why was it accepted or blocked?
\end{quote}
