\section{AION Phase 20P --- Mission Contract Integrity Layer}
\label{sec:aion-phase20p-mission-contract-integrity}

\subsection{Status}

Phase 20P locks the mission contract integrity layer.

\begin{quote}
\textbf{Status: LOCKED --- aggregate mission behaviour is evaluated before runtime mount.}
\end{quote}

\subsection{Purpose}

A mission can be unsafe even when each individual step appears safe in isolation.

Phase 20P detects cases where safe-looking steps combine into forbidden outcomes.

\begin{quote}
\textbf{Individually safe steps MUST NOT combine into a forbidden mission outcome.}
\end{quote}

\subsection{Forbidden Aggregate Outcomes}

The integrity layer detects aggregate paths into:

\begin{itemize}
  \item external message sending;
  \item payment capture;
  \item booking creation;
  \item production deployment;
  \item escrow creation;
  \item business memory mutation;
  \item live reputation write;
  \item scraping or exfiltration.
\end{itemize}

\subsection{Aggregate Sequence Detection}

The integrity layer MUST detect ordered sequences such as:

\begin{verbatim}
draft_customer_message
resolve_customer_contact
send_customer_message
\end{verbatim}

Even if earlier steps appear safe, the combined sequence is treated as a forbidden external message path.

\subsection{Tool-Combination Bypass Detection}

The integrity layer MUST detect tool combinations that create forbidden outcomes, including:

\begin{itemize}
  \item draft tool + contact lookup tool + external send tool;
  \item quote tool + payment payload tool + payment capture tool;
  \item page builder tool + bundle tool + deploy tool.
\end{itemize}

\subsection{Disguised Action Detection}

The integrity layer MUST detect disguised tokens in action names and payloads, including:

\begin{itemize}
  \item send;
  \item whatsapp;
  \item email customer;
  \item charge;
  \item capture payment;
  \item create booking;
  \item deploy;
  \item escrow;
  \item write memory;
  \item write reputation;
  \item scrape or exfiltrate.
\end{itemize}

\subsection{Runtime Mount Rule}

If any aggregate forbidden outcome is detected, runtime mount MUST be denied.

The mission runtime state MUST become:

\begin{verbatim}
blocked_for_safety
\end{verbatim}

For high-risk disguised findings requiring human review, the mission runtime state MAY become:

\begin{verbatim}
waiting_human_review
\end{verbatim}

\subsection{Threat Model Entry}

Observed bypass attempts from Home Fixed or other demo runs MUST be recorded as mission threat model entries.

Threat model entries MUST include:

\begin{itemize}
  \item mission ID;
  \item observed pattern;
  \item mitigation;
  \item source;
  \item deterministic threat model entry hash.
\end{itemize}

\subsection{Integrity Hash}

Every mission integrity evaluation MUST emit:

\begin{verbatim}
integrity_hash: sha256:<digest>
\end{verbatim}

The hash binds:

\begin{itemize}
  \item mission ID;
  \item mission run ID;
  \item findings;
  \item runtime mount decision;
  \item mission runtime state.
\end{itemize}
