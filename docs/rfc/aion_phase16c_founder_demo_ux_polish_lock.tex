\section{Phase 16C --- Founder Demo UX Polish and Workflow/A2A Preview Bridge}
\label{sec:aion-phase16c-founder-demo-ux-polish-lock}

\subsection{Status}

\textbf{Status: LOCKED.}

Phase 16C converts the simplified Boardroom front page from a developer-facing
lock surface into a founder-demo surface.

The lock keeps the main dashboard business-facing while preserving all advanced
runtime, Goal Engine, provider, AXO/ETS, evidence, memory, and trust diagnostics
inside the Advanced Runtime drawer.

\subsection{Purpose}

The decisive demo target is a clean, repeatable Home Fixed proof loop:

\begin{quote}
Home Fixed website/widget request
$\rightarrow$ Public Intent Gateway
$\rightarrow$ Guard Envelope
$\rightarrow$ AgentMap/capability route
$\rightarrow$ Machine Cart/quote preview
$\rightarrow$ Human Review handoff
$\rightarrow$ Founder decision preview
$\rightarrow$ FulfilmentJob preview
$\rightarrow$ Evidence preview
$\rightarrow$ Proof receipt preview
$\rightarrow$ ETS preview
$\rightarrow$ Boardroom replay.
\end{quote}

\subsection{Locked Front Page Sections}

The Boardroom front page MUST keep the following business-facing surfaces visible:

\begin{enumerate}
  \item Business pulse cards.
  \item Operator presence.
  \item Founder Demo Loop.
  \item Website and AgentMap setup card.
  \item Workflow-to-website-form preview card.
  \item Human Review Queue.
  \item Recent Replay / Proof Receipts.
  \item Advanced Runtime / Trust Debug drawer.
\end{enumerate}

\subsection{AgentMap Install Card}

The front page MUST NOT expose the raw full AgentMap dashboard as the primary
business-facing card.

Instead it MUST expose a compact website install card with:

\begin{itemize}
  \item AgentMap verification state.
  \item Shortened deterministic AgentMap hash.
  \item Hosted AgentMap URL.
  \item Well-known AgentMap URL.
  \item Website install tag.
  \item Generate, copy, download, and verify actions.
\end{itemize}

The full JSON and technical discovery internals MAY remain available in advanced
runtime surfaces.

\subsection{Workflow/A2A Preview Bridge}

The Boardroom MUST expose a preview bridge between workflow generation and A2A
machine discovery.

The workflow-to-website-form card MUST show:

\begin{itemize}
  \item selected workflow identifier;
  \item selected vertical adapter;
  \item public gateway route;
  \item AgentMap route;
  \item A2A capability;
  \item customer intake fields;
  \item generated embed-code preview.
\end{itemize}

This is a preview surface only. It does not create bookings, payments, escrow,
external messages, or live chain writes.

\subsection{Safety Boundary}

The founder-demo front page MUST visibly show:

\begin{itemize}
  \item No booking created.
  \item No payment created.
  \item No escrow created.
  \item No external message sent.
  \item No live chain write.
  \item Human review required.
  \item Replay/hash proof available.
\end{itemize}

\subsection{Replay and Proof}

The front-page proof panel MUST prioritize the Home Fixed founder-demo proof
path instead of exposing unrelated legacy marketing run lists first.

Marketing runs and other raw workflow runtime lists MAY remain available in the
Advanced Runtime drawer.
