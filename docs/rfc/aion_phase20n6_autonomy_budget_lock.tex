\subsection{Status}

\begin{quote}
\textbf{Status: LOCKED --- mission autonomy is budgeted, capped, and never allowed to create unapproved live side effects.}
\end{quote}

\subsection{Purpose}

AION Pilot requires mission-level caps for autonomous work.

The budget layer controls:

\begin{itemize}
  \item external reads;
  \item browser sessions;
  \item runtime minutes;
  \item safe steps before review;
  \item sub-plan depth;
  \item total steps;
  \item unapproved spend;
  \item unapproved public posts;
  \item unapproved production deployments;
  \item unapproved live customer messages.
\end{itemize}

\subsection{Default Live Side-Effect Caps}

By default, these values MUST remain zero:

\begin{verbatim}
max_spend_without_payload_approval: 0
max_public_posts_without_approval: 0
max_production_deployments_without_approval: 0
max_live_customer_messages_without_approval: 0
\end{verbatim}

\subsection{Progressive Trust}

Progressive trust MAY increase read-only or staged operating room.

Progressive trust MUST NOT remove exact approval requirements from always-approval actions.

\subsection{Trust Ladder}

The trust ladder contains:

\begin{itemize}
  \item \texttt{trust\_0};
  \item \texttt{trust\_1};
  \item \texttt{trust\_2};
  \item \texttt{trust\_3};
  \item \texttt{trust\_4}.
\end{itemize}

Higher trust MAY increase:

\begin{itemize}
  \item read-only external capacity;
  \item preview deployment capacity;
  \item staged workflow capacity;
  \item recurring template preparation.
\end{itemize}

Higher trust MUST NOT authorize:

\begin{itemize}
  \item unapproved payments;
  \item unapproved legal action;
  \item unapproved identity action;
  \item unapproved production deployment;
  \item unapproved domain purchase;
  \item unapproved new ad spend;
  \item unapproved live customer messages.
\end{itemize}
