\section{AION Phase 20H.6 --- External Webhook Callbacks and WebRTC Signaling Isolation}
\label{sec:aion-phase20h6-external-callback-signaling-isolation}

\subsection{Status}

Phase 20H.6 locks External Webhook Callbacks and WebRTC Signaling Isolation.

\begin{quote}
\textbf{Status: LOCKED --- external callback ingress and signaling channels are provider-scoped, mission-scoped, nonce-bound, replay-protected, and mutation-blocked.}
\end{quote}

\subsection{Purpose}

External execution does not end when AION sends or stages an action.

Providers may respond asynchronously through webhooks, callbacks, OAuth redirects, payment intent updates, deploy notifications, booking updates, sockets, or WebRTC signaling events.

AION MUST treat all inbound provider events as untrusted until they pass callback or signaling isolation checks.

\subsection{Callback Contract}

Every external callback contract MUST bind:

\begin{itemize}
  \item mission ID;
  \item mission run ID;
  \item business ID;
  \item provider;
  \item action type;
  \item callback type;
  \item callback URL ID;
  \item expected payload hash;
  \item staged state hash;
  \item provider context hash;
  \item nonce;
  \item expiry timestamp;
  \item consumed state;
  \item callback contract hash.
\end{itemize}

\subsection{Callback Ingress Assertion}

Before AION accepts a callback, it MUST assert:

\begin{itemize}
  \item callback has not already been consumed;
  \item callback is not expired;
  \item provider matches;
  \item mission ID matches;
  \item mission run ID matches;
  \item callback type matches;
  \item callback URL ID matches;
  \item nonce matches;
  \item payload hash matches the expected payload hash when one exists;
  \item callback does not request a forbidden mutation.
\end{itemize}

\subsection{Replay Rejection}

A callback event hash MUST be emitted for every inbound callback.

If the callback event hash has already been seen, the callback MUST be quarantined as replayed.

\subsection{Forbidden Callback Mutations}

Callbacks MUST NOT directly execute:

\begin{itemize}
  \item external action commit;
  \item business memory mutation;
  \item content publication;
  \item customer message sending;
  \item payment capture;
  \item production deployment;
  \item booking creation;
  \item DNS connection.
\end{itemize}

Callbacks may report status. They MUST NOT grant themselves execution authority.

\subsection{Signaling Contract}

Every signaling contract MUST bind:

\begin{itemize}
  \item mission ID;
  \item mission run ID;
  \item business ID;
  \item provider;
  \item browser worker ID;
  \item browser session hash;
  \item signaling channel ID;
  \item allowed signal types;
  \item expiry timestamp;
  \item signaling contract hash.
\end{itemize}

\subsection{Signaling Message Assertion}

Before AION accepts a signaling message, it MUST assert:

\begin{itemize}
  \item signaling contract is not expired;
  \item mission ID matches;
  \item mission run ID matches;
  \item provider matches;
  \item browser worker ID matches;
  \item browser session hash matches;
  \item signaling channel ID matches;
  \item signal type is allowed;
  \item signal does not request a forbidden mutation.
\end{itemize}

\subsection{Forbidden Signal Mutations}

Signaling messages MUST NOT directly:

\begin{itemize}
  \item commit external actions;
  \item approve payloads;
  \item mutate memory;
  \item write business container outputs;
  \item send messages;
  \item make payments;
  \item deploy.
\end{itemize}

\subsection{Quarantine Rule}

Any failed callback or signaling assertion MUST move the inbound event into quarantine.

If any callback or signal in a batch is blocked, the summary runtime state MUST become:

\begin{verbatim}
callback_signal_quarantine
\end{verbatim}
