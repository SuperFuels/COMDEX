\section{AION Phase 20N.4 --- Approval Lattice and User Override Safety}
\label{sec:aion-phase20n4-approval-lattice-user-override-safety}

\subsection{Status}

Phase 20N.4 locks the Approval Lattice and User Override Safety layer.

\begin{quote}
\textbf{Status: LOCKED --- user overrides may make execution stricter, but may never weaken system safety.}
\end{quote}

\subsection{Purpose}

AION Pilot allows the user to configure mission autonomy.

However, user configuration MUST NOT bypass the classifier, kernel guard, approval rules, checkpoint rules, or blocked state.

\subsection{Control Lattice}

Control modes form an ordered safety lattice:

\begin{equation}
\mathtt{autonomous}
\prec
\mathtt{human\_approval\_required}
\prec
\mathtt{human\_task\_required}
\prec
\mathtt{blocked}
\end{equation}

\subsection{Effective Decision}

Let $\mathcal{D}_{\mathrm{system}}$ be the system decision and $\mathcal{D}_{\mathrm{user}}$ be the user override.

The executable decision is:

\begin{equation}
\mathcal{D}_{\mathrm{effective}}
=
\sup
(
\mathcal{D}_{\mathrm{system}},
\mathcal{D}_{\mathrm{user}}
)
\end{equation}

Where $\sup$ is the least upper bound on the safety lattice.

\subsection{User Override Rule}

The user MAY make a step stricter.

The user MUST NOT make a step looser.

Examples:

\begin{itemize}
  \item \texttt{autonomous} MAY become \texttt{human\_approval\_required};
  \item \texttt{autonomous} MAY become \texttt{blocked};
  \item \texttt{human\_approval\_required} MUST NOT become \texttt{autonomous};
  \item \texttt{blocked} MUST NOT become \texttt{autonomous}.
\end{itemize}

\subsection{Policy Override Violation}

If the user attempts to weaken the system decision, AION MUST emit:

\begin{verbatim}
policy_override_violation: true
runtime_mount_allowed: false
fail_closed: true
reason: policy_override_violation
\end{verbatim}
