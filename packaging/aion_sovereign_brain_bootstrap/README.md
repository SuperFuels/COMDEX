# Set up your Pilot brain

This developer preview creates a new, empty AION brain owned by the person running it. It contains
no customer data, demo identity or provider key.

The separately named `AION Sovereign Brain Offline macOS arm64` package is the qualified
network-disconnected reference bundle. It includes a verified relocatable Python runtime, an
exact binary wheelhouse, Ollama and the Gemma 3 1B model. Run `Set Up Pilot Offline.command` to
verify the package and open setup, or `Run Offline Proof.command` to execute the included useful
meeting-summary and task-extraction proof with all supported paid-provider keys removed.

- macOS: double-click `Set Up Pilot.command`.
- Windows: run `Set-Up-Pilot.ps1` from PowerShell.
- Linux: run `./set-up-pilot.sh`.

The setup page opens only on this computer. It profiles coarse CPU, memory and storage capacity,
creates the mother identity and empty canonical stores, initializes the encrypted local vault and
recommends a local model class. The sovereign business-map store is a registry pointing to the
existing Boardroom `BusinessMapContainer`; it does not create a second competing business map.
New business workspaces begin with evidence-empty Boardroom containers and no demo company.
The existing schema-driven Boardroom foundation interview is saved as a revisioned mother-brain
session so trusted surfaces can resume it without making browser storage authoritative.
The canonical map now includes governed facts and relationships, owner review and correction,
deterministic links to approved source claims, and retention, legal-hold and revocation controls.
The existing Boardroom also provides one optional connection screen for Files, Gmail, Google
Calendar, CRM/Sales and Xero. It reports secret-free health and aggregate evidence counts only;
an owner must start each account connection, and imported evidence requires review before it can
become canonical company knowledge.
The bootstrap includes the provider-neutral intelligence contracts and router. Local,
customer-cloud and optional external compute all pass through the same disclosure, residency,
quality, cost, latency, energy and context limits. External adapters receive only fields the
owner policy declared, and route receipts retain hashes rather than private prompts or results.
Its signed model catalogue verifies trusted manifests and immutable artefact hashes before
installation, checks hardware and licence compatibility, separates repeatable public benchmarks
from customer-private outcome scores, and permits promotion only through bounded measured
canaries. Revocation, regression or provider drift blocks the affected model and rolls an active
route back when a previously qualified champion is available.
Replaceable compute plug-ins support local Ollama, private OpenAI-compatible services and
NVIDIA NIM-compatible endpoints through the same AION contract. Remote endpoints require HTTPS,
credentials remain vault references resolved only when called, and customer-cloud recipes remain
owned by the customer's account. CPU, Apple Silicon and NVIDIA profiles and explicit air-gapped,
no-paid-AI and premium-enabled modes prevent a provider from becoming the brain.
Signed capability packages declare their tools, scopes, limits and independently versioned
prompt, procedure, tool and policy components. Activation requires dry-run, adversarial permission
and outcome evidence plus a named human owner and approval. Undeclared access is denied, use is
bounded, and revocation or removal ends authority without deleting the customer's brain.
For growing organisations, the included medium-business operating model binds multiple legal
entities, divisions, locations, projects and matrix teams to the existing Boardroom workspaces
and Business Maps. It separates currencies, scopes every person's workspace, enforces delegated
approval and separation of duties, and applies customer-defined residency and retention rules.
The governed-improvement ledger keeps corrections separate from verified outcomes, expires stale
route preferences, proposes rather than silently creates automation, and admits training data only
with an approved licence, consent, purpose and prior redaction. Reviewed model changes require
elapsed retention and source-disjoint transfer evidence and retain a customer-visible rollback.
Commercial controls bind signed editions to a tenant without binding or inspecting its content.
Optional compute metering retains units, cost and provider receipt hashes only, and operational
diagnostics remain off until the customer enables specific zero-content categories. Ownership,
export and provider-replacement guarantees apply independently of edition.
The small cross-platform bootstrap does not automatically download a model or connect a cloud.
The explicitly labelled macOS arm64 offline bundle already contains its qualified local model;
neither package silently connects an external model provider.

The included runtime supervisor performs bounded health checks and automatic restart with a
cooldown and a finite failure ceiling. Its update manager accepts only releases signed by a
configured trusted publisher, verifies every declared file before staging, switches the active
version atomically and restores the previous healthy release when the candidate fails its
post-start health check. The mother brain retains a signed hash-chained local update history.
The developer preview contains the mechanism but no production publisher trust anchor; that
public key is installed only by the eventual signed platform package.

This is an unsigned developer preview. Consumer distribution still requires platform-specific
code signing, notarization/package signing and clean-machine qualification.
