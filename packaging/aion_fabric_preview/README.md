# Pilot Fabric Preview 0.66.0

Version 0.64 adds the commercial-assurance foundation without centralising customer
brains. Edition licences are cryptographically signed, tenant bound, expiring and
independent of customer content. Optional compute usage records quantities, costs and
provider receipt hashes but rejects prompts, responses, messages, documents and secrets.
Telemetry is disabled until the customer enables named categories; diagnostics contain
only component state, duration and error codes. Public guarantees preserve customer brain
ownership, export, provider replacement and useful local operation. Independent security,
legal and real-customer qualification remain explicit release gates.

Version 0.63 adds continuous governed improvement. Corrections and independently
verified outcomes are stored separately from conversation, route preferences are
specific to a task class and expire, and automation is only proposed after repeated
fresh success. Approval does not silently activate execution. Dataset admission binds
licence, consent, purpose, redaction and content hashes without copying raw content into
the registry. Fine-tunes, adapters and distillations are reviewed releases with rollback,
elapsed retention and source-disjoint unfamiliar-transfer gates. Customers can inspect
what changed, why, and reverse supported changes.

Version 0.62 adds the medium-business Boardroom operating layer. One customer-owned
brain can now represent a group of legal entities, locations, nested divisions and
unconventional or matrix teams without treating job titles as authority. Project
portfolios retain team, milestone, risk, work, budget, commitment, actual, forecast
and model-spend evidence while keeping unlike currencies separate. Enterprise identity
subjects map to scoped people; delegated approval, separation of duties, escalation,
residency, retention and provider-region rules fail closed. Employee, freelancer,
adviser, accountant and director views are bounded, and support/audit exports require
explicit authority and omit customer content and secrets. Every entity remains bound
to its existing Boardroom workspace and canonical Business Map.

Version 0.58 completes the unified sovereign-intelligence contract. AION now has
one request, structured response, stream-event and adapter contract for local,
customer-cloud and optional external intelligence. It enforces declared external
fields and residency before a call, bounds quality, cost, latency, energy and
context, isolates unhealthy routes with persistent circuits, makes retries
idempotent, stores hash-only route receipts, and delivers results only to Pilot
presentation or an approval-gated capability authority.

Version 0.57 completes the Business Map bootstrap connector stage. The existing
Boardroom now shows Files, Gmail, Google Calendar, CRM/Sales and Xero in one
plain-language connection screen. Loading the screen performs no provider write or
account connection. It exposes only health and aggregate container projections;
credentials and private provider content stay with the mother brain. An owner starts
OAuth explicitly, and imported evidence still requires review before it becomes
canonical company knowledge.

Version 0.55 moves the existing Boardroom foundation interview's progress to a
revisioned mother-brain authority. Trusted phone, desktop and television surfaces
can resume the same packet; stale devices fail closed instead of overwriting newer
answers. Browser storage remains an offline cache and one-time migration source.
Completion still requires the existing separate Business Map commit boundary.

Version 0.54 binds the Sovereign Business Brain to Boardroom's existing
`BusinessMapContainer` instead of creating a second map.  Existing workspaces are
registered without rewriting them; new workspaces use evidence-empty Boardroom
containers.  New fact proposals require provenance, confidence and owner review,
while corrections, rejection and confirmed deletion are revision checked and
receipt backed.  Quality queues expose proposed, stale, conflicting, incomplete
and missing-provenance records.

Version 0.53 repairs the downloadable boundary itself.  The release builder now
computes the recursive set of local Python modules actually imported by Fabric,
packages that narrow dependency closure, and excludes unrelated COMDEX intelligence,
live state and customer data.  The extracted archive is tested from outside the
source checkout and can run both its command-line entry point and provider-free
local demonstration.  It does not turn this preview into the signed consumer installer.

Version 0.52 adds the official persona-bound SMS delivery boundary, including exact
E.164 routing, idempotency and signed provider callbacks while keeping provider
acceptance, carrier delivery and human reading separate. It qualifies representative
mobile layouts, hardens call/group authority against adverse ordering and compromised
participants, and reuses the hidden Wave fragmentation and store-forward foundation.
The legacy radio bridge now has no default secret, requires replay-protected header
authentication and disables development mock routes by default. Physical radio
delivery, live provider accounts and independent media/security review remain external.

Version 0.51 adds persona-private Communication and Calendar workspaces plus the
first safe Pilot Guardian proof. Communication drafts through AION Native first,
binds approval to the exact recipient and content, protects child identities with
a guardian gate, records received-message provenance, and requires a verified
provider receipt. Calendar create, reschedule, cancel, conflict and availability
flows use exact private scopes and disclose no other event titles. Google account
connection uses a PKCE system-browser boundary and retains only an opaque vault
reference. Guardian provides a large, cancellable trusted-contact alert flow with
separate emergency and location permissions, connectivity fallback and two-way
response records. It never diagnoses a fall or claims ambulance dispatch.

Version 0.50.1 keeps spoken contact delegation deterministic when the local
speech model renders a saved name phonetically, such as Becca as ``back'' or
``backup''. Pilot accepts the repair only when it identifies one unique private
contact; ambiguous names fail closed and require private selection. These task
commands can no longer fall through into generic trip or research planning.

Version 0.50 adds a persona-private contact book and recipient routing for spoken
tasks. Natural phrases such as ``add collect the dry cleaning tomorrow to my
tasks'' are deterministic rather than planned. A contact can link to a Pilot
identity, email address or WhatsApp number, entered manually or selected through
the browser Contact Picker when a trusted phone supports it. Pilot-to-Pilot tasks
arrive as acceptance requests. External handoffs require an exact private-phone
approval and remain visibly pending until the sender connects an authorized email
or messaging account; knowing a recipient address never grants sending authority.

Version 0.49 makes the private television workspace conversational rather than
phrase-sensitive. Natural logout, task, calendar, Boardroom, file, IoT and personal
work commands are handled deterministically and can no longer fall into generic
planning. Every private destination requires the active signed television lease and
automatically disappears when it expires. Pilot Home adds a neutral Personal Work
placeholder for research, writing, study and projects, while the phone controller
adds a one-tap Mouse / trackpad shortcut that arms the pointer for thirty seconds.

Version 0.48 turns signed identity activation into an exclusive television
workspace lease. A trusted phone acquires the shared screen for one person,
the lease locks after five minutes without activity, another identity cannot
silently take it over, and either the controlling phone or the explicit voice
command ``Pilot, log me out of the TV'' releases it immediately. The Pilot TV
home now reveals identity-gated Tasks, Calendar, Business, Files and IoT tiles
while keeping private content absent whenever the workspace is locked.

Version 0.45 closes the locally enforceable Entertainment Intelligence scope.
Shared-TV viewing feedback now waits for private-phone identity claim instead of
being assigned to the household. Watchlists are persona-private unless explicitly
shared. Deterministic recommendations can rank provider-supplied candidates by mood,
duration, time and presence without paid AI or another person's unconsented history.
Episode reminders require an exact provider/content/episode identity and remain in the
local private inbox until native push exists. Provider health and sign-in recovery
never inspect credentials. Exact official provider routes, private confirmation,
signed playback/entitlement telemetry, continue-watching preparation and cross-room
handoff retain their existing verification boundaries.

Version 0.44 adds the locally enforceable Contextual Companion and Wellbeing
foundation. Companion mode is persona-bound and opt-in, with off/low/balanced/active
frequency, quiet hours, daily proactive limits, reading level and large-control phone
presentation. Advert quizzes require advert-break evidence and all offers are
dismissible and playback-preserving. Loneliness support explicitly identifies Pilot
as software, offers healthy next steps and can prepare a trusted-contact action.
Emergency or self-harm language crosses into a Guardian escalation boundary that
never claims diagnosis or dispatch. Shared-room support must be claimed privately;
TV-phone-car continuation transfers a bounded objective/summary rather than raw
transcripts; call preparation never places a call without a separate authorized adapter.

Version 0.43 closes the locally buildable Live Companion expansion. It adds
broader exact-current-cast credits, strict filming/location/source evidence,
joke/reference/cultural explanations, child and reading-level modes,
accessibility descriptions, learning activities, bounded cooking/object evidence,
product-claim verification, incident timelines, supplied lineups and explicit-range
historical team statistics. Private identity-bound close-event alerts, no-money
household predictions, a repeatable fact-check benchmark and verified private-phone
fact-check delivery are included. Subtitle projection, dubbing, native overlays,
audio DSP and official highlights are now protected by explicit fail-closed platform
and rights gates; the package does not pretend unavailable authority exists.

Version 0.42 begins Live Companion expansion with evidence-backed programme cast
questions. After Pilot has established a stable programme identity, “who is in
this?” and “show me the cast” retrieve the public TVmaze main-cast record, while
“who plays [character]?” requires an exact character match. “Who is that actor?”
never triggers face recognition or visible-person guessing: Pilot states that it
cannot identify the person on screen and offers the verified cast instead. Cast
data is bounded, cached for twenty-four hours, attributed, and displayed on the
private phone while television playback remains untouched.

Version 0.41 adds provider-independent programme identity to production screen
perception. On a media surface, Pilot extracts bounded OCR title candidates but
does not trust one camera frame. A title must repeat across the multi-frame
window before it can be sent to the public TVmaze catalogue. Only one strict,
normalized exact match is accepted; ambiguous or approximate matches remain
unverified. Catalogue identity, current playback, regional availability and
account entitlement are separate facts. Only signed provider telemetry can
verify playback. Catalogue queries are cached for twenty-four hours, capped at
one hundred records, contain no pixels or account data, and retain TVmaze
attribution. The phone shows the evidence source and each verification boundary.

Version 0.40 advances production screen perception without claiming that a web
page is a native mobile observer. Visible Observer Mode now has Detail, Balanced
and Battery Saver profiles, owner-selectable two-, five- and ten-minute leases,
an explicit countdown, Pause, Resume and Stop controls, and privacy-safe session
receipts. The mother enforces the effective frame interval independently of the
browser, throttles reported low-battery or elevated-thermal clients, and rejects
frames when visibility, battery or thermal policy pauses a session. Two
consecutive frames on a changed application/input create a fresh context window,
preventing an old Netflix title or subtitle from leaking into YouTube, HDMI or
another surface. Browser capture still closes when the page is hidden and never
restarts invisibly; signed native iPhone and Android clients remain required for
production background execution.

This package is the isolated AION Device Fabric proof. It starts one local
mother node, loads a fridge/TV demonstration fabric, and opens a readable local

Version 0.33 adds a signed playback-telemetry boundary for native applications,
authorized account adapters and capable device nodes. Every packet is bound to
one provider, one private persona, an approved Ed25519 source identity, explicit
metadata/playback/entitlement scopes, a short timestamp window and a one-use
nonce. Forged, stale, replayed and cross-persona packets fail closed. Only
normalized title, content identifier, state, position, duration and separately
scoped entitlement status are retained; raw provider responses, account
identifiers and secrets are excluded. Matching telemetry can verify an exact
private entertainment execution and feeds the multi-frame perception timeline.
The ingestion endpoint exists only on the trusted HTTPS companion. This is the
provider-independent foundation: Netflix and other restricted services still
require their own authorized native/account adapters before Pilot can receive
these facts in the field.

Version 0.32 adds an optional HTTPS private companion on LAN port 8769. The
mother generates a private household root CA and a 397-day server certificate
locally with the already bundled cryptography library. The leaf certificate is
bound to the current LAN address, localhost and mother hostname. CA and server
private keys remain in the owner-only runtime directory; only the public CA
certificate is downloadable. The original port 8767 page becomes the explicit
trust/bootstrap route and redirects a correct pairing code to HTTPS. The laptop
shows the CA SHA-256 fingerprint for out-of-band comparison before trust is
enabled. HTTPS responses use TLS 1.2 or later, HSTS, CSRF protection, tokenized
paths, rate limits and the existing camera-only permissions policy. Pilot cannot
silently install or trust its CA: on an unsupervised iPhone the owner must review
the profile and separately enable full trust. HTTP remains available as a
recovery controller, but continuous camera use is offered only by the trusted
secure context.

Version 0.31 adds the first production-perception foundation. Observer and
manual phone frames now feed a bounded multi-frame timeline rather than allowing
one image to establish a programme or screen state. Two-thirds agreement across
at least two recent frames is required for a stable surface; programme titles
also require repeated metadata support. Duplicate frames are ignored. The
timeline retains at most twelve structured, hashed observations for ninety
seconds of active reasoning and never retains source pixels. Subtitle changes,
scene change, OCR playback position and provider title evidence remain separately
labelled. A short-lived observer frame lease can survive page suspension in the
same phone tab, but the camera restarts only after the user presses **Resume after
phone sleep**. Truly continuous background capture still requires trusted TLS or
a signed native phone application.

Version 0.30 adds the universal verified-navigation transaction. Private phone
navigation, media and app actions now begin with a device/surface belief and an
explicit success criterion. A signed transport receipt records delivery only.
Pilot then requires either permitted post-action device state or a structured
phone observation before declaring the goal verified. Failed observations can
offer a bounded recovery route; attempts stop after three. Successful and failed
routes are remembered separately for each television, surface and goal. The
phone shows the live transaction, expected outcome, attempt count and whether a
new screen capture is required. Raw camera frames remain deleted after local
analysis.

Version 0.29 adds verified entertainment execution. Cross-service discovery
results remain evidence until the private phone selects an exact official title
or video route. Pilot accepts narrowly validated Netflix, YouTube, Prime Video,
and Disney+ routes, strips non-canonical query data, rejects search/catalogue or
credential-bearing URLs, and binds the prepared route to one household persona.
The phone must confirm the exact title and provider before a device attempt.
Opening the app or provider is recorded as `provider_open_verified`; it is not

both the title and a playing state. The last verified route can be prepared for

Version 0.28 adds governed saved-item follow-through. Every product, recipe,
destination, song, learning concept or idea saved from television can now be
researched privately, converted into a local shortlist/task/learning draft, or
used to prepare a shopping, trip or music proposal. The source item must belong
to the active phone identity. Research has no external effect. Consequential
conversions create a new exact service scope and a separate phone approval; the

Missing trip dates are collected privately. Approval stops at

Version 0.27 adds Live Event Intelligence. “Pilot, who scored?”, “show the
statistics”, “show the fixtures”, “what’s the score?”, and “show upcoming
concerts” route through provider-independent live-event intelligence. An

Version 0.26 adds programme-to-private saving. “Pilot, save this product,”

Version 0.25 adds evidence-bounded Live Sports. “Pilot, what’s the score?”

Version 0.23 adds spoiler-aware Live Companion explanation. “Pilot, what just

Version 0.22 completes the first private Pilot Moment sharing boundary. “Pilot,

Version 0.21 introduces the first consumer-reliability layer. Private phone and

Version 0.19 introduces AION Native Mode and removes cloud-first research.
Every request is routed through deterministic local capability, AION's local
state and memory, the installed local model, and bounded public evidence before
any optional provider is considered. AION Native forbids paid-model use. AION
+ Gemini permits a user-supplied Gemini key for inexpensive evidence synthesis

Version 0.10 introduces universal shared-device nodes and persona-bound service
execution. A device runtime is installed once. Previously confirmed mother
brains resume a stored public-key relationship; a new mother receives a
one-time locally confirmed handshake. Each mother then uses a short-lived,
signed, replay-protected capability lease rather than installing another node.
Calendar, email, messaging, shopping, booking, maps and music proposals are
bound to a private household persona. Only that persona may approve and execute
through its own opaque provider or vault binding. Raw cards and credentials are
rejected from proposals and never projected onto the shared TV.

The running node advertises its bounded handshake surface on LAN port 8768.
`/identity` exposes only the node ID, public key and policy. New relationships
use `/handshake/begin` and `/handshake/complete`; known signed mothers request
canonical capability leases through `/lease`. Requests are size- and
rate-limited, leases expire within 24 hours, and nonces cannot be replayed.

On macOS, double-click `Start AION Fabric.command`. On other systems, create a
Python virtual environment, install `requirements.txt`, and run:

```bash
python -m backend.modules.aion_fabric.cli serve --demo --open-browser
```

The private control dashboard binds to localhost. A separate token-protected,
read-only AION TV Canvas is available on the local network so an enrolled
television can display AION without receiving control credentials or private
COMDEX data.

Version 0.6.1 replaces the generic-planning search handoff with COMDEX's local
Gemma planning intelligence. It retrieves bounded web evidence, compiles a
strict structured objective plan, separates assumptions and missing constraints,
shows a coherent itinerary on TV, and keeps a voice follow-up window open so the
owner can refine dates, budget, party size, interests, or transport naturally.

Version 0.6.2 adds a true microphone sleep state. “AION, sleep” acknowledges
the request and closes the Mac input stream; no audio is captured while asleep.
Because a closed microphone cannot hear a wake phrase, the localhost dashboard
provides an explicit Resume microphone control.

Version 0.7 turns the private phone companion into an installable controller:
D-pad, volume, mute, playback, app launching, typed requests, task approvals,
live TV state, and contextual controls are routed back through the mother's
signed capabilities and audit ledger. An explicit phone-camera capture can be
analysed locally with Apple Vision to identify supported TV screens such as a
Netflix profile chooser or Google consent page. Source pixels are deleted as
soon as analysis completes. A follow-up capture verifies whether a preceding
navigation action produced the expected screen change. webOS TV itself exposes
no supported general screenshot interface, so camera perception remains
owner-initiated and visible.

Keep the terminal window open while using the dashboard. Closing it stops the
local server.

This is a developer preview, not yet a signed or notarized consumer installer.
